# 0.29.0 预开发计划：YSM 特殊投射物弹幕

> 状态：0.29.0 已定版，OpenYSM 投射物渲染已完成实机验证。十字类与 action 字段属于
> 实验性契约；本文记录当前实现边界，不把兼容层伪装成稳定的跨模组 API。

## 1. 目标

0.29.0 保留一个统一的实验性 `custom` 十字类，用于少量需要更高辨识度、但不希望
遮挡视线的非 Billboard 弹幕（例如封魔阵、小刀、苦无）。任意 `fire_danmaku` action
都可以附加 YSM 投射物模型渲染；没有对应模型时回退到该弹幕自身的 YH 基础渲染。
两条路径共享同一条服务端飞行轨迹、碰撞、擦弹和生命周期。

本版本直接删除原有四个专用弹幕类型、物品注册、资源和编辑器选项。它们没有事实性
下游符卡应用，不设计存档别名、序列化迁移或长期兼容层。十字类仍作为可直接选择的
基础弹幕保留，YSM 不再要求使用某一种 bullet。

## 2. 背景与边界

普通 YH 弹幕使用客户端缓存中的虚拟 `SimplifiedProjectile`，由批处理渲染器绘制，
适合大数量弹幕。YSM 投射物模型通常需要逐实例处理模型、骨骼和绘制调用，适合少量
特殊弹幕，不应替换 YH 的大规模路径。

Shooter 已经是 YH 的真实 `LivingEntity`，继续复用现有 YH→YSM LivingEntity 委托。
Boss 模型、Shooter 模型和十字类弹幕模型属于三个独立作用域：Boss 或 Shooter
切换模型不能改写已经生成的弹幕。弹幕 action 的模型配置在生成时快照，缺失时只让
受影响的弹幕回退到 YH。

YSM/OYSM 是软依赖。没有模组、API 不兼容、模型包或槽位不存在时，YH 必须继续启动，
Boss、Shooter、普通弹幕和符卡逻辑不受影响。

## 3. 资源分发边界

`D:\IdeaProjects\MC模组\资源\剑圣魂魄妖梦_1.0_pro` 只能作为开发者本机 `run` 目录的
调试资源和测试素材。它不得进入 `src/main/resources`、版本库、JAR、整合包或发布附件，
也不能成为构建或运行时的硬依赖。

开发环境移除该目录后，模组仍应构建和启动；相关模型探测失败时回退到 YH。测试脚本
可以读取本机可选路径，但不得复制、下载或自动打包其中的文件。

## 4. `custom` 类型

`YHDanmaku.Bullet.CUSTOM` 是保留的十字类基础弹幕，YH 路径使用稳定的 Cross 几何和
`circle/white` 基础贴图。它不携带旧类型的变体字段，也不通过旧注册名提供别名。需要
不同形状、贴图或模型时，使用 `ysm_projectile` 覆盖表现，而不是增加新的枚举项；该
覆盖同样适用于 `circle`、`ball`、`spark` 等其他 bullet。

弹幕的尺寸语义必须分成两层：

1. **`base_scale`**：弹幕实例的基底尺寸，沿用现有实体权威同步和判定链；它可以影响
   模型最终大小、碰撞/判定箱、视角剔除以及其他依赖实体尺寸的逻辑。
2. **`model_scale`**：模型局部变换，只影响 YSM 或其他自定义模型的显示大小，不改变
   碰撞箱、判定箱、视角剔除、服务端运动或伤害。视觉尺寸通常为
   `base_scale × model_scale`。

`model_scale` 不能由客户端模型文件自行决定，必须来自符卡定义或已同步的 action
配置。YH 回退没有 YSM 模型时忽略该字段，但仍遵守 `base_scale`。

## 5. Action 级选择

首期按 `fire_danmaku` action 选择模型。一个 action 产生的弹幕共享同一套投射物配置；
需要混用 YH 和 YSM 时拆成两个 action，不按单颗弹幕保存模型字段。

当前 Codec 接受以下字段；`size` 仍可作为旧字段读取，`base_scale` 同时存在时优先，
以便旧符卡继续工作。新保存或导出的 JSON 只写 `base_scale`：

```json
{
  "type": "fire_danmaku",
  "bullet": "circle",
  "color": "white",
  "count": 2,
  "speed": 0.25,
  "lifetime": 100,
  "base_scale": 1.0,
  "ysm_projectile": {
    "model_source": "fixed",
    "model": "模型包 ID",
    "slot": "arrow",
    "model_scale": 1.0,
    "max_instances": 8,
    "fallback": "yh",
    "acknowledge_cost": true,
    "offset_forward": 0.0,
    "offset_right": 0.0,
    "offset_up": 0.0
  }
}
```

- `bullet` 仍决定无 YSM 时使用的基础渲染；附加 `ysm_projectile` 不改变运动、伤害、
  碰撞或擦弹语义。`custom` 只是可选的十字类，并非 YSM 的必要入口。
- 不填写 `ysm_projectile` 时完全走 YH 回退路径。
- `model_source: fixed` 由 action 明确指定模型包或模型 ID；未来若支持
  `boss_current`，也必须在生成时捕获并快照，不能隐式继承 Boss 当前模型。
- `slot` 是模型包中的投射物槽位，必须由 YSM 探测结果确认；槽位缺失即回退。
- `max_instances` 限制同时进入 YSM 路径的可见实例数，超出部分立即走 YH。
- `fallback` 首期只支持 `yh`，保证没有 YSM 时仍有画面。
- `offset_forward`、`offset_right`、`offset_up` 是模型局部坐标偏移，单位与模型缩放前的
  投射物模型一致，分别表示前、右、上；三个字段只移动渲染模型。
- `acknowledge_cost` 是符卡创建者对逐实例渲染成本的显式确认，不是运行时绕过上限
  的开关。

模型位置、朝向、染色和生命周期参数由 YH 弹幕状态提供。桥接层不能创建第二套物理
实体，也不能因为模型渲染失败改变服务端轨迹。

这里的“模型可用”仍受 OpenYSM 自身资源格式约束：当前 OYSM 会把一个模型包整体装配为
`ModelAssembly`，因此投射物模型包需要能被该版本 OYSM 正常加载；只声明了
`files.projectiles` 并不意味着可以绕过 OYSM 的模型包校验。YH 不依赖某个测试模型的
固定 ID，加载成功后会按实际 `projectiles` 槽位工作。

## 6. YSM 桥接和回退

当前实现使用 YH 自有兼容层：对每个进入 YSM 路径的可见弹幕缓存一个客户端内存
Projectile 代理，代理类型按选中的槽位解析（例如 `minecraft:arrow` 或
`minecraft:trident`），复制 YH 的位置、旧位置、朝向和 tick，再反射调用 OpenYSM 的
`CustomProjectileRenderer.renderProjectile` 与 `ProjectileCapability`。代理不加入世界、
不参与物理、碰撞或伤害；服务器仍只管理 YH 弹幕。桥接层接收 `base_scale`、
`model_scale` 和 action 快照，调用失败统一回到现有 YH 路径。

`slot` 不是模型骨骼名，而是 YSM `projectiles` 映射中的 Minecraft 实体类型。编辑器会
从当前模型已加载的 projectile map 读取可用槽位并以下拉菜单显示；`main`、`arm` 等
LivingEntity 主体部件不属于 projectile 槽位，不能用于这里；vehicle 或其他非
`Projectile` 实体也不会被这个入口接受。`model_scale` 与 YH 的 `base_scale` 相乘后施加到
YSM 模型；`offset_forward`、`offset_right`、`offset_up` 在投射物局部坐标中换算到世界
位置，只影响模型 PoseStack，不影响判定箱、轨迹或服务端实体。代理按弹幕 ID 缓存，
模型在模型 ID 变化时更新，槽位变化时重建代理，并在客户端换世界、登出或资源包重载时清理。

如果未来 OpenYSM 改变投射物入口，应继续限制在显式启用的少量 action，并保持服务端由
YH 管理状态。不得把所有弹幕实体化，也不得修改 OYSM/YSM 第三方源码；兼容代码使用
反射、事件或 YH 自有适配类。

## 6.1 符卡 Editor 清理与 Shooter 抽象

0.29.0 收窄符卡侧的 `ysm_render` 节点。当前 `/yhysm editor` 已完整承载模型绑定、
预设、原生动画片段、表情参数和清理操作，符卡节点不再重复这些设置；它只保留
`hint` 与 `duration`，用于把 `cast`、`charge` 或 `special=...` 等 legacy YSM
上下文提示交给客户端渲染选择器。空 hint 清除旧 hint，`duration: 0` 保持到显式清除。
该节点仍保留 `ysm_render` 类型 ID 以便分析器识别，但旧 `operation` 模型/预设/参数
字段不再属于当前 Codec 契约，且没有仓库内符卡依赖这些已移除语义。

Shooter 的初始模型、纹理、hint、持续时间和清理目标改为共享 `YsmRenderConfig`，
序列化在 `spawn_shooter.ysm` 下统一表达。旧的 `ysm_model`、`ysm_texture`、
`ysm_animation`、`ysm_duration`、`ysm_clear_target` 扁平字段仍可读取，以便已有
实验数据平滑进入新表示，但新 Editor 和导出只写嵌套配置。Boss、Shooter 和弹幕
仍各自保存生成时的表现快照，不共享运行时模型状态；YSM Editor 负责持久模型绑定，
符卡节点只负责短时提示或 action 级渲染选择。

桥接层缓存代理和模型状态；编辑器只在打开槽位菜单时读取当前模型的 projectile map，
渲染循环不反复反射、加载资源或创建模型对象。缺失能力、模型、槽位和超限都走同一个
YH 回退，不产生每帧日志。

朝向核对结论：YH `ProjectileMovement` 与原版投射物都用 `yaw = -atan2(x, z)`、
`pitch = -atan2(y, horizontal)`；但 OpenYSM 的 `AbstractProjectileRenderer` 会对
Arrow 代理再应用 `yaw - 90`，而 YSM 投射物模型按 +X 轴建模时与 YH 的 yaw/pitch 符号
相反。桥接层因此只对**渲染代理**镜像 yaw、pitch（同时镜像 old yaw、old pitch）；YH
实体的物理朝向和轨迹不变。修正后 `+X/-X/+Z/-Z/+Y/-Y` 六个方向均应与速度一致；
实机仍需沿这六个方向核对模型尖端与轨迹一致；
若第三方模型自身轴向不同，应通过模型资源或局部 offset 调整，不改动弹幕物理朝向。

## 7. 告警、确认和性能

当 action 含有 `ysm_projectile` 时，Editor 和 Analyzer 显示一次性能告警，至少包含：
模型来源、槽位、`max_instances`、YSM 路径、YH 回退路径和预计实例数。未设置
`acknowledge_cost: true` 时，认证分析会阻断该 action（除非是 operator test），
Editor/Analyzer 同时显示告警；运行时不会因为该字段改变 YH/YSM 回退。

运行时只允许一次性或汇总诊断，不能在渲染循环逐帧刷日志。需要覆盖的诊断包括 YSM
缺失、API 不兼容、模型/槽位不存在和达到实例上限。

预开发基准先覆盖 0、8、20 个同时使用 YSM 的实例，并分别记录 GPU、CPU、
Compatibility 后端和无 YSM 环境的帧时间与绘制批次数。8～20 只是初始设计范围，不是
不可调的硬常量；默认上限进入 `YHModConfig` 或 action profile，不能在渲染器里再放一份
隐藏默认值。

YH 回退和 YSM 路径必须分开测量。模型资源定型后，如果数量需求上升，应评估烘焙为
YH 批处理模型，而不是无限提高 YSM 实例上限。

### 7.1 普通弹幕的碰撞默认值

普通 `fire_danmaku` 缺少 `hit_behavior_entity` 或 `hit_behavior_block` 时，0.29.0
按历史行为解析为 `continue`。这只改变缺省值，不覆盖 action 中已经写出的字段。

妖精内置符卡的弹幕会同时显式写出实体和方块 `discard`，保证妖精的原有表现不随
全局默认值变化。非符限制器仍要求非符弹幕在两种碰撞上都显式/解析为 `discard`；
普通弹幕默认值恢复不等于放宽非符规则。

### 7.2 非符限制器开发旁路

为支持整合包作者和 OP 快速探索非符形态，提供服务端命令：

```text
/yhdev bypass_spell_limiter [true|false]
/yhdev bypass_spell_limiter <targets> <true|false>
```

命令要求权限等级 2。第一种形式操作当前玩家，第二种形式可由玩家或控制台指定
在线目标。开关按玩家 UUID 保存在当前服务器进程内，不写入符卡 JSON、存档或客户端；
服务器停止时清空。

开启后，该玩家的新非符会跳过 `NonSpellValidator` 的发射前结构/性能校验，并跳过
非符的单 tick 生成额度；服务端仍权威执行运动、碰撞、伤害和生命周期。已有非符也
会在运行期读取开关。关闭后，下一次刷新会重新按当前 Power 校验；若定义不再满足
限制，则停止继续生成并让已在飞行中的弹幕自然结束。该旁路只用于开发和调试，不改变
认证、普通玩家或默认平衡规则。

### 7.3 全局自定义符卡

面向整合包的自定义符卡放在游戏实例根目录的：

```text
youkaishomecoming_spells/<namespace>/<path>.json
```

该目录与 `saves/` 同级，不属于某个世界；例如
`youkaishomecoming_spells/my_pack/example.json` 对应符卡 ID
`my_pack:example`。OP 可以用 `/yhspell export <namespace:path>` 将当前注册定义导出到
该目录，命令反馈会给出实际路径。服务器启动时先加载全局目录，再加载当前世界的
`<world>/youkaishomecoming_spells/`。每次服务器启动会先恢复默认定义，避免上一个存档
的自定义符卡残留。全局文件允许覆盖同 ID 的 Java 内置定义；世界
目录中的同 ID 定义再优先于全局文件，但不会覆盖 Java 内置定义。整合包应把全局目录
中的 JSON 与资源包/数据包一起分发，并保证定义不依赖某个存档才存在的运行时状态。

## 8. 分阶段实现

### Phase 0：类型清理与契约探测

- 删除四个旧类型的枚举、注册物品、标签、模型、贴图、编辑器选项和源码引用。
- 保持 `CUSTOM` 十字类的 YH 回退可用，确认普通 bullet 和预览均可附加 YSM 配置。
- 探测目标 YSM 版本的投射物入口、模型槽位和反射签名，记录失败回退。
- 冻结 action 级配置、模型来源快照、`base_scale`/`model_scale` 和 `max_instances` 语义。

### Phase 1：少量弹幕桥接

- 实现 YH 虚拟弹幕到 YSM 的可选渲染桥，保持服务端权威和 YH 回退。
- 首先验证位置、旋转、染色、尺寸、出生/销毁时机和共同飞行轨迹。
- 在无 YSM、槽位缺失和超限三种情况下验证同一条回退路径。

### Phase 2：Editor、Analyzer 和确认

- Editor 支持 action 级模型包、槽位、上限、`model_scale` 和三轴局部偏移配置；模型 ID
  下拉选项实时来自当前 YSM 已加载模型。
- Analyzer 显示模型成本和回退路径；保存/认证前记录创建者确认。
- 预览允许同一符卡拆分 action，分别观察 YH 和 YSM 表现。

### Phase 3：本地测试素材和风格调试

- 只从 `run` 目录读取本机模型包，验证投射物槽位、贴图、染色和模型调试效率。
- Shooter 继续单独使用 `main.json` 的 LivingEntity 管线，不与弹幕槽位混用。
- 记录实机截图或 `/yhysm debug` 快照，不把测试素材写入模组资源。

### Phase 4：基准和启用范围

- 完成 0/8/20 实例和不同后端基准，调整配置默认值与认证告警级别。
- 只有在实机证明画面、回退、生命周期和碰撞轨迹正确后，才扩大默认启用范围。

## 9. 验收条件

- `Bullet` 中保留统一的 `CUSTOM` 十字类；旧四类型的代码、资源、标签、生成模型和
  编辑器候选全部不存在。YSM 配置可附加到任意 bullet。
- 无 YSM、API 不兼容或模型缺失时，模组可构建、启动和正常运行，受影响弹幕回到 YH。
- 构建产物和发布包不包含本机妖梦模型包；移除 `run` 测试素材不会阻断构建。
- action 明确附加 `ysm_projectile` 且模型可用时才进入 YSM；模型缺失回退该 bullet 的
  YH 基础渲染。Boss、Shooter 和弹幕模型互不覆盖。
- `base_scale` 会按现有权威链影响实体尺寸相关行为；`model_scale` 只影响模型显示。
- 达到上限的实例稳定回退且没有每帧日志；模型缓存不会随每帧创建销毁。
- Editor/Analyzer 能显示成本、槽位、上限、回退路径和确认状态。
- 实机确认少量十字类及其他 bullet 的 YSM 弹幕朝向、贴图、染色、局部偏移、出生/销毁和共同飞行轨迹，且碰撞、
  擦弹和伤害与 YH 路径一致。
- 提交前通过 `git diff --check`；渲染改动还需实机截图或 `/yhysm debug` 证据。

## 10. 风险与未决问题

1. 当前按槽位创建对应的原版 `Projectile` 代理，依赖 OpenYSM 投射物模型对实体类型的映射；
   没有注册实体类型、没有对应 projectile 槽位或模型尚未就绪时回退 YH。
2. 模型槽位命名和元数据格式必须以实际 YSM 版本探测结果为准，不能假设 LivingEntity
   槽位可直接复用。
3. 玩家 `main.json` 的 MoLang 和姿态逻辑可能不适合 Shooter 或投射物，需要专用资源
   或适配层。
4. `acknowledge_cost` 未确认时的认证阻断级别需要结合现有认证流程决定。
5. 当前兼容层用 `VertexConsumer` 包装器乘入 YH tint/color animation；不同 YSM
   RenderType 是否都遵守顶点色和 alpha 必须实机确认，未通过前应使用 YH 回退或记录为
   已知限制。
6. 透明度、深度和渲染层顺序需要实机确认，不能破坏法阵、阴影和实体委托链。

## 11. 0.29.0 实机测试清单

测试前将获授权的模型包仅安装到本机 `run` 实例的 OpenYSM 模型目录，记录实际模型 ID；
测试完移走该模型包再跑一次软依赖回退。不要将模型包复制到源码资源目录。

### 11.1 启动与软依赖

- [ ] 不安装 OpenYSM 启动客户端和单人世界，普通弹幕及 `custom` 十字类均正常显示。
- [ ] 安装目标 OpenYSM 版本启动，日志没有 linkage error、类加载失败或逐帧重复告警。
- [ ] 使用错误模型 ID、缺失模型包和没有对应 projectile 槽位的配置；均显示 YH 回退且不崩溃。
- [ ] 触发同一种失败至少 10 秒，确认每个原因只记录一次告警。
- [ ] 资源包重载、退出世界再进入、退出服务器再重连，确认代理重新绑定且旧模型不残留。

### 11.2 模型作用域与显示

- [ ] 用本文第 5 节的最小 action 分别测试有效模型 ID和错误模型 ID。
- [ ] Boss 使用一个 YSM 模型、Shooter 通过现有 `main.json` 管线使用另一个模型，弹幕 action
  指定投射物模型；三者互不改写，切换 Boss/Shooter 模型不改变已生成弹幕。
- [ ] 同一符卡拆成两个普通 bullet action，其中一个附加 YSM，另一条保持 YH，确认两条路径同时可见。
- [ ] 检查出生第一帧、销毁前一帧、出视野再返回，以及符卡结束后的模型清理。
- [ ] 红、蓝、绿、白和 `color_animation.hue_cycle` 能乘入模型；自机淡出、远距淡出、
  弱化透明度及透明贴图没有明显深度排序错误。

### 11.3 轨迹、朝向与判定

- [ ] 测试直线、环形、扇形、球形，以及 homing、acceleration、bounce mover；模型中心始终
  跟随同一 YH 弹幕位置，朝向与速度方向一致，没有双实体或尾随一帧。
- [ ] 单独发射沿 `+X/-X/+Z/-Z/+Y/-Y` 的六组单发弹幕，逐组确认 YSM 模型尖端与速度同向，
  特别回归此前的 `+X` 反向问题，并确认 `+Z/-Z` 不被连带翻转；必要时只调模型局部 offset。
- [ ] 检查 `on_expiry`、`on_trail`、`on_hit_entity`、`on_hit_block` 的时机与 YH 回退一致。
- [ ] 用 F3+B 确认唯一判定箱来自 YH 弹幕；YSM 模型几何不产生额外碰撞、伤害或擦弹。
- [ ] 缺省碰撞行为对实体和方块均为 `continue`；显式 `discard` 立即移除，显式 `expire`
  执行过期回调；妖精内置符卡仍在两类碰撞上 `discard`。

### 11.4 两层尺寸

- [ ] 交叉测试 `base_scale = 0.5 / 1.0 / 2.0` 与 `model_scale = 0.5 / 1.0 / 2.0`。
- [ ] `base_scale` 同时改变最终模型、判定箱及实体尺寸相关剔除；`model_scale` 只改变显示。
- [ ] 最终视觉大小符合 `base_scale × model_scale`；改变 `model_scale` 不改变轨迹、擦弹、
  碰撞或伤害。
- [ ] 读取只含旧 `size` 的 JSON 后行为不变；从编辑器保存或 `/yhspell export` 后只出现
  `base_scale`。

### 11.5 告警、认证与非符旁路

- [ ] 编辑器启用 YSM Projectile 后能从实时模型 ID 下拉菜单选择模型，并从当前模型的
  projectile map 下拉选择 `arrow`、`trident` 或其他已声明实体槽位；模型尺寸、前右上偏移、
  实例上限和确认项均可编辑。Analyzer 显示模型、槽位、上限及选中 bullet 的 YH 回退信息。
- [ ] `acknowledge_cost: false` 阻断普通认证，改为 `true` 后通过该项；operator test 可测试
  未确认定义，但不会改写保存值。
- [ ] 非 OP 无权执行 `/yhdev bypass_spell_limiter`。OP 测试查询、`true`、`false` 以及
  `<targets> <true|false>` 四种形式；控制台无目标形式给出用法提示。
- [ ] 开启后可发射原本被 `NonSpellValidator` 或单 tick 配额拒绝的非符；已有非符立即采用
  旁路。关闭后重新校验并停止不合规的后续生成，飞行中弹幕自然结束。
- [ ] 旁路不跳过物品 cast-ready、beaten、EX trait、运动、碰撞、伤害及生命周期规则；
  重启服务器后旁路状态恢复关闭。

### 11.6 全局符卡与跨世界隔离

- [ ] `/yhspell export test_pack:custom/arrow_test` 生成
  `<game>/youkaishomecoming_spells/test_pack/custom/arrow_test.json`，内容为 UTF-8。
- [ ] 两个不同存档都能加载该全局 ID；世界目录中的同 ID 自定义符卡覆盖全局自定义符卡。
- [ ] 全局定义可覆盖 Java 内置 ID；当前世界文件不能直接覆盖 Java 内置 ID，加载优先级与
  第 7.3 节一致。
- [ ] 从存档 A 返回标题并进入存档 B，A 独有的世界符卡不出现在 B；删除/重命名 A 的文件
  后重进不会从静态注册表复活。
- [ ] 旧版下划线扁平文件及旧 Windows 编码文件能迁移到目录式 UTF-8 路径；owner sidecar
  随世界文件迁移，删除时新旧路径及 sidecar 都被清理。

### 11.7 性能基准

- [ ] 在相同视角、分辨率和模型下分别记录 0、1、8、20、32 个 YSM 实例的 FPS、
  CPU 帧时间、GPU 帧时间和 draw calls；每档至少观察 30 秒并记录 1% low。
- [ ] 0 个 YSM 实例时普通 Billboard 弹幕性能相对 0.28.9 无可测退化；8 个为首要目标，
  20 个用于压力观察。
- [ ] 将 `max_instances` 设为 8 后生成 20 个，只有前 8 个进入 YSM，其余稳定走 YH 回退；
  不出现每帧代理创建、持续内存增长或日志刷屏。
- [ ] 分别测试原版渲染、Embeddium、Oculus/光影的实际整合包组合；记录异常 RenderType、
  alpha、深度和崩溃日志。
