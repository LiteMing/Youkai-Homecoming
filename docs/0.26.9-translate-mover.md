# 0.26.9 Translate Mover

## Coordinate space

`translate` keeps its historical default:

```json
"space": "world"
```

In world space, `x/y/z` are east-west, up-down, and south-north offsets.
Existing JSON without `space` is unchanged.

Set `space` to `local` to evaluate the three formula offsets in the projectile's
launch frame. This is an implementation coordinate frame, not a second angle
control API:

```text
x = forward
y = right
z = up
```

The frame is captured once when each projectile is emitted. It is based on the
final initial velocity, after aim, origin rotation, tilt, and `group_rotation`
have been applied. Authors should use `group_rotation` for angles: `rot_y` is
yaw, `rot_x` is pitch, and `rot_z` is roll (rotation within the firing plane).
Those providers are sampled at emission time, so a formula such as
`"rot_y": "phase_tick * 3"` rotates successive emissions without changing a
projectile's frame during flight.

## Two tick meanings

The `tick` in `group_rotation` and other `NumberProvider` fields means the current
spell phase tick. It is evaluated once when the action emits a projectile. For
example, this rotates successive emissions without changing a projectile's frame
later:

```json
"group_rotation": {
  "rot_x": "sin_deg(tick * 0.5) * 10",
  "rot_y": "tick * 3",
  "rot_z": 0
}
```

The `tick` in `translate` x/y/z formulas means that projectile's flight tick.
It can animate the offset while the captured frame remains fixed:

```json
"mover": {
  "type": "translate",
  "space": "local",
  "x": "tick * 0.2",
  "y": "2 * cos_deg(tick * 4)",
  "z": "2 * sin_deg(tick * 4)"
}
```

Use `phase_tick` or a `NumberProvider` variable when a value must be sampled at
emission time rather than follow the projectile's flight tick.
