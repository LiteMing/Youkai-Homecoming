## 用户目标与首期范围

让 YH 战斗、日常行为、脚本、符卡 Editor 和手动指令都能方便地调用 YSM 格式模型的
动作、表情及外观参数。使用者能够查看模型实际具备的能力、试播、停止、设置持续时间、
恢复状态，并把验证过的操作用于正式玩法。

0.28.0 首期覆盖 YH 妖怪/Boss、发射器，以及对应的 Editor 预览对象。玩家和 TLM 女仆
各自的动作控制不在首期扩展范围；现有渲染委托与软依赖回退继续遵守 `AGENTS.md`。

继续以当前 OYSM 版本为适配基线。官方 YSM 的接入单独评估，不作为本版本前置条件。

- 整合包内的旧版 `/yhysm` 只提供模型/纹理绑定与调试；本开发分支新增直接播放、停止、

- 模型元数据中的 `extra_animation` 可能指向动作、子菜单或配置组，不能把每个条目当动画。
  `extra_animation_buttons.config_forms` 中的表情/外观控件可能执行 Molang 或修改变量。

## 0.28.0 交付内容

### 1. 模型能力查看与试播

- 按目标实体/模型查看真实动画片段、转盘动作、配置控件及其选项或数值范围。
- 读取已载入模型的元数据，保留名称、标签和实际标识之间的对应关系；无需使用者猜测 `extraN`。
- 命令补全与 Editor 共用目录查询。明确区分未安装 OYSM、API 不支持、模型未就绪、模型缺资源。
- 调试信息显示请求、实际选中项、当前覆盖来源和剩余时间；解析失败可定位到模型和条目。

### 2. 动作与表情控制

- 动画提供播放、停止、重播和持续时间；单次、循环、保持末帧模式逐项验证后提供。
  不用一个循环动画加计时器冒充已支持所有播放语义。
- 表情/外观参数支持读取、设置、到期恢复和清除；优先使用模型声明的控件和取值范围。
- 身体动作与表情参数分别管理，允许一次语义动作同时设置动画和多个表情参数。
- 明确覆盖来源与优先级：战败投影保持权威，显式动作能够覆盖普通日常动作；
  同一参数的新请求不能被旧请求的到期清理覆盖。清除恢复到当前有效基础状态。
- 服务端持有请求、目标、开始时间、到期时间和必要的重播标识，客户端仅执行表现。
  处理模型尚未载入、重新进入跟踪范围、切换模型、重载资源、实体移除和断线清理。
- 全量快照与瞬时动作区分：恢复持续状态时不把已结束的一次性动作重新播放；
  客户端缓存重建后按剩余有效期应用，而不是重新计时。

### 3. 命令、脚本、Editor 与日常行为共用入口

当前实现的常用入口如下；完整语法、权限、恢复与公共脚本契约见
`docs-dev/yhmodel-script-api.md`，逐步操作见 `docs/ysm-editor-user-checklist.md`：

```text
/yhysm editor
/yhysm inspect [实体]
/yhysm anim play <实体> <动画名> [持续tick]
/yhysm anim stop <实体>
/yhysm param list [实体]
/yhysm param set <实体> <参数名> <值> [持续tick]
/yhysm param clear <实体> [参数名]
/yhysm preset list <模型>
/yhysm preset apply <实体> <模型> <预设ID> [持续tick]
/yhysm clear <实体>
/yhysm state <实体>
```

当前播放语义为 LOOP + 有效期；没有开放 once/hold 或最初草案中的 `action` 命令。
命名意图使用模型内的预设 ID 表达，不按 `extraN` 推断含义。

- 世界修改命令支持服务端选择器、权限检查和脚本调用；客户端的目录查询或补全不充当权限依据。
- Java 与 KubeJS 提供同一套有文档的调用语义；新公开接口登记并同步 Java/KubeJS 两端。
  不把客户端目录能力设为专用服务端执行脚本的前提。
- Editor 使用相同请求与解析逻辑，提供补全、试播、停止和恢复。
  预览状态与真实世界隔离；暂停、重播、时间轴回退不能遗留表情或重复执行一次性效果。
- 至少接通一个战斗场景和一个日常场景，证明接口可在符卡以外复用；
  首期不重写全部角色的日常 AI。
- 保留现有 `/yhysm` 绑定命令、`ysm_render` 内容及已发布脚本契约的兼容行为，
  新能力以明确的新增入口接入，不能借改名改变旧内容语义。

#### 3.1 第三种模式：YSM Editor（维护者补充，纳入 0.28）

与符卡、魔法阵共用现有 Editor 壳和停靠机制，YSM 模式有独立布局、草稿和保存状态。
已在真实绑定／目录／预设消费者接通后加入三模式循环与 `/yhysm editor` 直接入口。
YSM 模式沿用其他 Editor 模式的单人暂停逻辑，不绕过现有网络保存链路；本地预览有独立时钟。
联机/已开放局域网世界由 Minecraft 按原规则保持运行。

| 模式 | 配置对象与职责 |
|---|---|
| 符卡 | 弹幕动作与战斗流程；通过统一接口调用角色表现，不承载整套模型适配表 |
| 魔法阵 | 魔法阵结构与表现资源 |
| YSM | 实体 UUID/type 绑定、逐模型原生能力目录、可复用动作／表情预设组、状态与事件映射 |

YSM 工作区应直接提供以下操作：

- 选定实体 UUID 或实体 type，查看有效模型／纹理、绑定来源与覆盖关系，编辑、保存、禁用或还原绑定。
  复用现有服务端 `YsmOverrideData` 持久化和广播，不能另建一份只在本机生效的真绑定表。
- 选择已载入模型，分别浏览真实动画、转盘条目、子菜单和表情／外观控件；保留原生标签、参数名、
  选项及范围。同一个转盘条目同时关联动画与配置组时，两种能力都保留，不强行二选一。
- 分类、预设和触发项使用下拉；模型沿实际 ID 目录分层，并读取可用的原生包名称，候选旁提供隔离小预览。
  动画按名字前缀分层，不把推断分类冒充来源 JSON。表情只显示选中参数，不平铺所有控件或不能执行的脚本。
- 提供 Raw JSON 标签，复用现有多行文本控件的选区/撤销，编辑 `format=1` 预设、triggers 与可选 binding；
  未应用原文保留，保存前校验，JSON 与表单双边修改拒绝静默覆盖。不修改原生模型资产。
- 顶栏主操作为“保存并绑定”，其余保存方式在“更多”。组合操作先确认预设保存，再绑定当前 UUID/type；
  后一步失败明确提示部分完成，不能把预设保存误报成绑定成功。Ctrl+S 保留仅保存共享预设配置的语义。
- 窗口缩放重建保留当前模式的布局快照；模式切换仍按稳定键分开保存，不重置用户魔法阵布局文件。
- 将一个身体动画和零至多个参数值保存为有稳定 ID 的 YH 预设；预设按模型限定，
  不把 `extra5` 或 `v.roaming.mouth` 当成所有模型通用的语义。
- 对下列状态／事件指定预设、期限和回退；预览可模拟触发，不修改真实实体的 AI、姿态或战败状态。

| 触发项 | 触发性质与权威来源 |
|---|---|
| 弹幕战开启 | 服务端开始实际 tick 符卡；不能每帧重播 |
| 换卡 | 已在弹幕战时开始另一张符卡；不含普通 phase 或并行子图 |
| 近战命中 | 妖怪真实 `doHurtTarget` 返回成功后 |
| 受伤 | 服务端有效受伤事件；连续命中时采用明确的覆盖／重播策略 |
| 待机、走路、飞行 | 持续状态投影；退出状态恢复当前有效基础表现 |
| 战败、下坠、倒地 | 直接跟随既有 beaten 三相位；倒地持续到权威状态结束，不能由动画结束反推 |

状态映射和瞬时事件分开处理。优先级按身体动画与每个参数分别合成，
战败投影 > 显式脚本／命令／符卡请求 > 战斗／受伤表现 > 日常状态；
战败映射缺失时继续既有 `special=` 模型无关回退链。
上述层级已由 `YsmPresentationResolver` 实现并有契约覆盖。身体显式请求之下保留旧符卡 hint 层；
连续受伤采用最新有效命中重播、重新计时。同 tick 的两次命中也增加序号，持续状态不每 tick 重播。

#### 3.2 原生目录与服务端共享预设的边界

- 原生模型目录来自实际加载模型的客户端，不能要求专用服务器通过客户端渲染 API 读取资产。
  Editor 可以从原生控件创建／导入受支持的数值预设，但不会自动执行任意模型内嵌 Molang 脚本。
- 由 Editor 保存的 YH 预设组和条件映射必须服务端持久化、校验、同步；
  真实绑定／预设保存与本地试播是不同操作，多人编辑需处理版本冲突，不能静默覆盖别人的修改。
- 脚本要能枚举指定模型／实体的**已登记可用预设组**、读取其描述并应用到具体实体，
  也保留底层单动画、单参数修改接口。脚本取回的是服务端共享定义，不伪称“所有客户端当前拥有的资产”。
- 已登记 `YHModel.listModels/listPresets/describePreset/profileJson/applyPreset` 和 `format=1`
  可导出 JSON；底层 `play/setParameter/stop/clear` 继续保留。服务端查询共享定义，不读取客户端原生目录。
- YSM 模式与其他模式切换时先处理未保存草稿；试播、清空、重播和关闭界面必须清理隔离预览，
  不能把模拟的进入战斗／受伤／倒地操作发送为真实世界战斗状态。

### 4. 逐模型动作映射

- 由世界共享的逐模型配置维护 `cast`、`happy`、`angry` 等自选稳定预设 ID 到原生片段、参数组合的映射。
  配置保存于世界 SavedData，可通过 Editor 导出／导入 `format=1` JSON；原生 `ysm.json` 不是此导入格式。
- 映射区分动画片段、预设操作和模型参数，允许为不同模型配置不同实现。
- 新映射依据验证过的模型能力，不按 `extraN` 的序号推断动作含义。
- 缺少合适资产时明确反馈并使用已配置的回退；战败表现继续遵守既有动画与几何兜底边界。
- 用现有内置模型与至少一个能力结构不同的模型验证映射，记录各自的缺失项和实际效果。

## 工程边界

- 命令、Editor、脚本和日常行为是真实消费者，可共用一个窄的 YH 表现控制入口；
  不为尚未接入的实现预建 Backend/Registry/Factory。
- OYSM 类名、方法探测、Molang 执行及元数据差异收在 YH 自有兼容层，能力缺失时独立降级。
  不修改 OYSM/TLM 源码，不改变冻结的 `ExternalLivingRenderAPI` 签名。
- 动画和模型参数不能反向决定伤害、碰撞、资源、战败相位或 AI 规则。
  不改变 `SpellCircleLayer → YSM → TLM → super` 的既定委托顺序。
- 模型能力缓存随模型/资源生命周期失效；反射方法缺失需缓存结果，渲染循环不刷日志。
- OYSM 未安装时模型专属安装与调用按实际能力关闭，主模组、脚本和 Editor 能正常降级。
- 数值上限和可调策略使用 `YHModConfig`；本地化遵循中文分片生成、英文手工维护的双来源规则。
- 本版本不承诺为所有模型补齐动画、不建设通用骨骼重定向系统、不批量改写第三方模型资产。

## 验收与完成定义

- 从查看一个已绑定的 YH 实体开始，能够找到并试播真实动作、调整表情、停止并恢复；
  找不到资源时能看懂原因。
- 同一操作能够通过手动命令、脚本和 Editor 执行，战斗与日常消费者行为一致。
- 两名观察者看到一致的持续状态；晚进入跟踪范围、模型延迟加载、模型切换与断线不会遗留状态。
- 重播同一动作确实重新开始；单次/循环/保持模式按已声明能力工作；
  参数到期清理不会撤销后来设置的新值。
- 无 OYSM、无 TLM 组合能够启动；保留既有模型绑定、符卡动作和软依赖回退。
- 战败三相位、落地与倒地保持、治疗恢复、隐身认证目标及完整弹幕战无回归。

- 渲染、动画与同步验收必须有实机截图或 `/yhysm debug` 快照及联机结果；
  编译和静态接口核对不能替代实机验收。
