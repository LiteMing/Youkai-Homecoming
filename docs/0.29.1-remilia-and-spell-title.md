## 蕾米莉亚

- 数据驱动内置 `touhou_little_maid:remilia_scarlet` 的瞬移使用世界轴相对偏移：
  `offset_x/y/z = (target_x/y/z - caster_x/y/z) / 2`。沿用 `caster` 原点与现有碰撞检查，
  不改 `caster_facing` 或 `teleport` 的通用语义。
- 冈格尼尔蓄力末段和发射弹柱都沿施法者到目标的三维连线排布，发射从实际弹幕原点瞄准目标，
  不受实体视线尚未转向目标的影响。
- 激光节点收敛为 `burst(20, 1) → repeat(4) → 主束 + repeat(3) 分叉`。
  仍为 20 tick、每 tick 4 组、共 320 条激光；主束 25–40 格，分叉 80 格，预警时序保留。
  每组在执行时采样共用方向、长度和分叉转角。分叉起点严格位于主束末端，绕主束间隔 120°、
  张角 45°。球面随机使用等面积纬度采样，不再在 Java 创建符卡时固化 320 个随机发射节点。

已保存的独立符卡副本保留自己的节点内容；要使用新的内置结构，重新从内置符卡创建副本。

## `show_spell_title`

符卡名仍只来自 `SpellDefinition.display.name`。演出现在包括入场、停留和移入活动符卡栏，
`duration` 包含全部三段。移动期间保持标题可见；背景图片和说明退场；结束后由同一 HUD 行接续。
终点读取活动符卡栏实际的排序、锚点、偏移和缩放，默认在右上角。关闭活动符卡栏时只播放开场演出。

新增可选 `presentation` 对象，编辑器的标题动作属性栏提供同样的字段：

```json
{
  "type": "show_spell_title",
  "duration": 100,
  "radius": 64,
  "presentation": {
    "background": "kubejs:textures/gui/portraits/remilia.png",
    "background_scale": 1.0,
    "background_x": -40,
    "background_y": 30,
    "gradient_direction": "top_to_bottom",
    "gradient_start": "#CC224F96",
    "gradient_end": "#00224F96"
  }
}
```

- `background` 是资源包内 PNG 的完整资源 ID。省略时不绘制图片；缺失或无法读取时静默跳过图片。
  图片先按原始宽高比适配开场区域，再应用 `background_scale`；`background_x/y` 为相对开场中心的
  GUI 像素偏移，正值分别向右、向下。图片有独立的入场位移和缩放。
- 两端颜色使用 `#AARRGGBB`、`0xAARRGGBB` 或带符号的 ARGB 整数。`gradient_direction` 支持
  `left_to_right`、`right_to_left`、`top_to_bottom`、`bottom_to_top`。颜色字段分别表示所选方向的
  起点和终点，移入活动符卡栏后保留相同方向。旧节点省略方向时沿用客户端默认值，初始为左到右。
  两端 alpha 都设为 `00` 可关闭底色。
- 未指定的数值由 `YHModConfig.CLIENT` 的 `hud.spell_title` 分组提供：开场缩放、开始移入的时长比例、
  默认图片缩放/偏移、默认渐变方向和颜色。动作只保存作者明确覆盖的值；“重置标题样式”恢复客户端默认值。

背景图通常使用角色立绘。编辑器的“背景图资源 ID”与 JSON 的 `presentation.background`
共用 Minecraft 标准资源路径 `命名空间:路径`，可直接引用原版、模组、资源包或 KubeJS assets 中的 PNG。
例如上面的 `kubejs:textures/gui/portraits/remilia.png` 可以由以下任一来源提供：

| 来源 | 图片放置位置 |
|---|---|
| 已启用的资源包（相对资源包根目录） | `assets/kubejs/textures/gui/portraits/remilia.png` |
| KubeJS（相对游戏目录） | `kubejs/assets/kubejs/textures/gui/portraits/remilia.png` |

资源 ID 保留 `textures/` 和 `.png`，填写时省略磁盘路径中的 `assets/` 及其之前的目录。
原版纹理也可直接引用，例如 `minecraft:textures/item/apple.png`。同 ID 资源沿用 Minecraft
资源包覆盖优先级；新增或替换图片后按 F3+T 重载，再触发标题演出即可。服务端同步资源 ID 与样式，
观看者客户端需加载提供该图片的资源。

### 编辑器实时预览

选中 `show_spell_title` 节点后自动打开“标题预览”停靠面板，并暂停 3D 符卡场景。
初始停在立绘完整显示的停留帧；在属性栏修改显示名称、说明、图片资源 ID、缩放、偏移或渐变，
预览立即更新。显示名称仍修改 `SpellDefinition.display.name`，不会在动作内建立第二份标题。

- 背景图选择沿用 YSM hint 的输入框、下拉箭头和文件夹交互：先筛选资源命名空间（留空为全部），
  再选择按资源目录分组的 `textures/` 内 PNG，或直接输入完整资源 ID（也支持其他目录）。只枚举当前启用资源包的最终资源，保持标准
  覆盖优先级；支持原版、模组和 KubeJS assets。更换筛选命名空间不会擅自替换当前背景图。
- 候选目录旁有小图片预览窗，鼠标悬停或上下方向键选中候选即可等比查看；透明部分用棋盘底显示。
  回车/点击才把候选应用到标题，Esc 收起。小窗空间不足时可使用原有完整标题预览面板。
  图片尺寸和资源目录缓存随 F3+T 刷新。缩略图仅按需读取当前候选，不预先解码全部资源图片。
- “播放 / 暂停”和“重播”播放完整的入场、停留及移入 HUD 动画；播放结束后保持停靠帧。
- “停留帧”便于调整立绘与渐变，“停靠帧”查看活动符卡栏中的最终样式。
- 拖动进度条可检查任意时刻；暂停后修改时长保留当前进度。点击预览面板后，空格播放/暂停，
  Home 重播，End 查看停靠帧，左右方向键逐 tick 查看。输入框获得焦点时沿用文字编辑按键。
- 面板按当前游戏 GUI 尺寸等比缩放画布，图片偏移仍使用游戏 GUI 像素。预览一张敌方符卡，
  复用实际 HUD 的位置、锚点、缩放和标题绘制；关闭活动符卡栏时也会预览结束后隐藏的行为。
- 更换图片 ID 或用 F3+T 重载资源包会刷新图片缓存；无法读取图片时在面板底部提示。
  旧停靠布局会把新面板添加到视口旁边的标签页，布局可继续自行调整。

预览使用独立时钟，仅绘制当前选中的标题节点；实际战斗的标题提示和服务端 HUD 快照保持独立。

服务端为每次标题展示产生独立标识，并在标题提示与活动符卡快照中同时同步。不会凭相同名字匹配，
玩家代理、实体代理、不同施法者和同一符卡的再次展示可以正确区分。客户端等待稍晚到达的首次快照，
已确认的符卡结束后立即取消其未完演出。单人暂停时暂停动画；退出或切换世界时清理客户端状态。

**内部契约变更**：两个标题/HUD 网络包新增展示标识和样式，客户端与服务端须同时更新到 0.29.1。
运行时 NBT 新增 `SpellTitleId` / `SpellTitlePresentation`，旧存档仍可读取。既有符卡 JSON 无需迁移；
公开跨模组 API、KubeJS 事件和 OYSM 反射签名不变。

## 初始化的可选宣言衔接

编辑器选中 `spellcard_init`（`mode: set`）后，“宣言衔接（可选）”提供三个独立开关：

- “显示符卡标题”：关联 `show_spell_title`，点击“标题与立绘设置”进入原有属性与资源图片选择器。
  选中已开启标题衔接的初始化，也会直接显示完整标题预览。
- “展示手持符卡”：关联 `show_spell_card`，点击“符卡展示设置”调整持卡手、位置、缩放及持握/抛出/悬浮时间。
- “宣言期间无敌”：关联 `set_invulnerable`，在初始化面板直接编辑无敌时长（tick 数或数字表达式）。

三项默认均可不选，不影响原来的初始化参数。启用时复用初始化后紧邻的一组宣言动作；插入新动作按
无敌、标题、手持符卡排序，保留已经存在的参数和顺序。顶层和嵌套初始化都支持，不跨越其他动作、
延迟节点、分支或下一次初始化寻找关联。关闭开关使用既有 `disabled` 包装保留参数，重新开启恢复；
独立节点仍可在动作列表移动、删除或编辑，改动沿用撤销/重做与自定义名称同步。

JSON 仍保存独立的相邻动作，无需新的初始化字段，例如：

```json
[
  { "type": "spellcard_init", "health": 600, "duration": 1200 },
  { "type": "set_invulnerable", "duration": 100 },
  { "type": "show_spell_title", "duration": 100 },
  { "type": "show_spell_card" }
]
```

这些动作与初始化在同一 tick 启动。符卡时限、标题演出、手持符卡展示和无敌时长分别设置；无敌节点
默认不暂停发射。0.29.2 可以在其后添加独立的 `freeze_on_tick` action，让 `on_tick` 按该节点自己的
时长暂停并从原进度继续。
推荐放在宣言阶段的 `on_enter`；没有开启冻结时，仍可另用 `delay` 或阶段转换安排后续发射。

## 宣言期间的 Boss 无敌

编辑器“符卡流程”下新增“Boss 定时无敌”（`set_invulnerable`）。在宣言的 `on_enter` 列表中放置：

```json
[
  { "type": "set_invulnerable", "duration": 100 },
  { "type": "show_spell_title", "duration": 100 }
]
```

`duration` 是必填的数字提供器，单位 tick，100 tick 为 5 秒。节点与标题同时开始；0.29.2 新增独立的
`{"type":"freeze_on_tick","duration":100}` action。无敌节点本身不会暂停 onTick、Boss AI 或移动，
标题节点也不会阻塞动作列表。

- 仅保护正在运行符卡的 YH 妖怪/Boss，包括认证用 Boss；不赋予玩家、玩家代理或代理的所有者无敌。
- 服务端按世界 game time 保存截止时刻，在普通受伤入口拦截伤害，不消耗符卡血量，也不触发受击动作。
  原版标记为绕过无敌的伤害仍沿用原有规则；无需修改原版 `Invulnerable` NBT。
- 再执行时替换当前剩余时长，`duration: 0` 立即解除；普通阶段切换不重置截止时刻。符卡重置、
  重新开始阶段、换符卡或结束后旧保护失效。区块卸载/重载不会延长截止时刻。
- 新建节点的默认时长来自 `YHModConfig.COMMON.spellDeclarationInvulnerabilityTicks`，
  配置路径为 `danmaku_battle.spellDeclarationInvulnerabilityTicks`；
  节点保存后以自身时长为准。反复在 `on_tick` 执行会反复续期，宣言通常只放在 `on_enter`。
- 分析器登记 `set_invulnerable` 能力；0.29.2 将其标为 `[OP]`，普通认证与非符均不允许使用。

运行时 NBT 增加可选 `CasterInvulnerableUntil`，旧数据缺失该字段时按无保护处理。展示动画不驱动
服务端战斗状态，无敌和标题时长均由作者明确设置。
