# pre1fix：专用服弹幕同步的客户端类加载崩溃

2026-09-13 的专用服日志在蕾米莉亚弹幕碰墙后崩溃：
`YHBaseDanmakuEntity.syncBounceToClient` 构造 `DanmakuBounceSyncPacket`，触发
`ClientLevel` 在 `DEDICATED_SERVER` 上加载，被 Forge `RuntimeDistCleaner` 拒绝。
日志版本为 `0.30.0pre`，当前 pre1fix 分支也包含同一条未隔离的路径。

## 原因与修复

包类同时用于服务端构造/序列化和客户端接收。旧 `handle` 方法直接访问
`Minecraft.getInstance().level` 与 `ClientDanmakuCache`；JVM 在验证包类时就可能解析
`ClientLevel`，不必等到实际调用客户端接收方法。发送处的 `!level().isClientSide`
判断无法隔离这种类加载。

接收处理移入现有 `DanmakuClientHandler.applyMotionReset`，与生成、清除弹幕包沿用
同一客户端边界；该 helper 明确标为 `@OnlyIn(Dist.CLIENT)`。公共包只保留数据和委托，
不再直接引用 Minecraft 客户端世界或缓存。

`BOUNCE`、`HOLD`、`CONTINUE` 共用该包，因此三类同步一起修复。客户端继续调用原有
`applyBounceState`、`enterHoldState`、`applyContinueState`；其他投射物仍回退为位置与
速度/旋转更新。服务端继续负责碰撞与轨迹结果，未改反弹物理、网络字段、枚举、注册顺序、
配置或存档格式。

## 验证

`DanmakuPacketSideTest` 通过 30 项窄范围检查。测试用独立 classloader 禁止加载 Minecraft
客户端、渲染类和客户端 helper，加载真实生产包类，再通过真实 L2Serial/FriendlyByteBuf
进行序列化往返。旧代码在反射构造器时复现 `NoClassDefFoundError: ClientLevel`；修复后覆盖：

- 反弹、停驻、继续飞行三种模式的构造、编码、解码。
- 实体 ID、位置、速度、反弹计数与模式值完整保留，解码耗尽整个数据包。
- 无参构造、旧四参构造和空模式参数的反弹回退。
- 相邻生成、单个清除、批量清除弹幕包仍可构造。
- 整个构造/序列化过程不请求任何被禁用的客户端类。

入口：`dev.xkmc.fastprojectileapi.render.virtual.DanmakuPacketSideTest.main`，使用项目
test runtime classpath；本地记录为 `build/pre1fix-check/danmaku-side-before.log` 和
`danmaku-side-after.log`。测试仅初始化序列化所需的原版注册表，不启动游戏或 Forge 服务器。
尚未实测专用服蕾米碰墙以及停驻/继续飞行的客户端同步画面。

交付前集中执行 `compileJava organizeLang --offline`（1m 56s）和 `jarJar --offline`（12s），
使用 `-Pll_version=2.7.0+HCDRS_0.30.0pre1fix`，编译、语言生成、重混淆和 refmap 检查均通过。
包内公共类的客户端引用已移除，helper 的客户端标记与原状态分支保留；复制至主工作区后
哈希一致，记录在 `build/pre1fix-check/danmaku-side-artifact.json`。

合并复核：仅修改仓库内 virtual 包的公共同步包和现有客户端 helper，未改模组入口、
上游构建/语言生成器、第三方依赖源码或公开跨模组契约。修复独立提交到 pre1fix 后同步
`0.30.0`。候选 JAR 和哈希见 [构建记录](0.30.0pre1fix-llmcore.md#候选包)。
