# pre1fix：JSON 覆盖确认与失效草稿恢复

Raw JSON 自动应用前，只判断是否会改变另一个已注册 ID 的内容，不增加符卡校验层：

- 工作区当前选中的 ID：普通修改，不弹确认。
- 未注册的新 ID：直接载入工作区。
- 另一个已有 ID，但 Codec 编码后的内容相同：直接载入。
- 另一个已有 ID，内容不同：复用 `ConfirmScreen` 提示，接受后才应用；之后这个 ID 已是当前选中项，后续修改不再提示。

完整解析和既有坏节点抢救共用这一入口。取消保留原工作区和注册内容，并把粘贴文本保存成
未应用草稿。Raw JSON 面板跨确认弹窗重建保留文本/草稿状态，避免取消后丢文本或重新弹出。
确认只将内容载入当前客户端工作区；实际注册覆盖仍经过原来的显式保存及服务端处理。
本功能针对编辑器已经掌握的注册表，不新增跨客户端并发编辑锁或服务器覆盖协议。

2026-09-13 将面板的纯 JSON 解析/丢字段诊断提取为 common `SpellJsonChecker`，并把
`SpellJsonSalvage` 移到 common definition 包，供编辑器与 AI 修订共用。界面的草稿保存与覆盖
确认仍留在原面板中；AI 生成不注册或自动应用符卡。提取后 8 项覆盖判断检查再次通过。

嵌套条件的合法默认值曾因 Codec 编码省略，被 Raw JSON 误报为不支持字段。共用检查器现按

## 删除符卡后的草稿恢复

此前删除只移除了注册表和存储中的定义，物品 `spell_id` 仍然保留；再次使用只提示未知符卡，
洗白配方又将失效 ID 复制到产物里。`DynamicSpellItem.clearMissingDraftBinding` 统一处理
未完成、未认证草稿的失效绑定，仅移除 `spell_id`，保留等阶、预算、灵气特性和其他物品数据。

- 服务端接受删除后，立即解除删除者背包和副手中对应草稿的绑定，并同步物品；同一编辑器
  会话可以接着新建，不必先退出或重新制作基底。
- 旧存档、箱子或其他玩家手里的失效草稿，在下次使用时由服务端恢复为空白草稿，进入原有
  编辑入口。先尝试已有的 `minecraft:path` → 玩家命名空间迁移，成功恢复的绑定继续保留。
- 水桶／水瓶洗白与升阶产物也会清理失效绑定；有效 ID 继续保留原来“退回草稿编辑”的行为。
  配方只修改产物副本，不修改合成材料；灵气转换仍保留原绑定，使用时处理旧 ID。
- 自动恢复不重置完成卡或已认证卡；后者仍可通过证书快照使用，不依赖当前可编辑定义。

`SpellDraftRecoveryTest` 通过 34 项窄范围检查：真实 ItemStack NBT 保存／读取、元数据保留、
命名空间迁移、删除后的背包／副手解绑、重新绑定，以及真实配方的洗白／升阶／灵气转换。
`SpellCombatEntryTest` 的 29 项资格检查再次通过。没有启动游戏，右键开窗、删除后立即创建和
实际容器同步仍需实机验收。未新增 JSON 检查器、配置、提示确认或网络包字段。
