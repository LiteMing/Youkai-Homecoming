# pre1fix：LLM Core 用途注册与计费预算

修复基于 `0.30.0` / `fc5a85081`，单独保存在 `0.30.0pre1fix`。
pre2/barrier 暂存于 `feat/0.30.0-barrier-completion` / `fd823f196`，随后仅回移修复提交。
候选包通过 `-Pll_version=2.7.0+HCDRS_0.30.0pre1fix` 命名，不修改版本字段或发布远端产物。

原实现没有注册 `PurposeMeta`，所以控制台用途列表不显示 `YH_SPELL_GENERATION`；
请求仍可能通过默认路由进入 orchestrator，但计费上下文固定为 1 次调用和 12,000 token。
第一条凭据失败后，后续凭据/provider 尝试会触发 `Causal chain call budget exhausted`，
长能力报告或较大的输出上限也可能触发 token 预算拒绝。

`YhLlmCoreBridge` 现在通过 Forge common setup 注册用途，注册不依赖 AI 开关、服务器 runtime
或首次生成请求。请求时保留幂等补注册。未安装可选库时不阻止 YH 加载。

请求仍使用 `LlmRequest.routed` 和 `SharedLlmRuntime.current()`，继承控制台的用途/默认路由
及参数。在完整 system/user 消息构建后调用 `LlmOrchestrator.estimateWorstCaseBudget`，
将返回的调用次数/token 上限写入 `LlmBillingContext.player`。预算覆盖所选路由的凭据重试和
provider 回退；请求 ID 同时作为 causal root，独立生成请求各有一个新 ID。
这不会修改 llmcore 的个人预算、计费主体或准入策略。预算 API 缺失或失败时返回错误，
不再吞掉反射异常后发送缺少计费信息的请求。

集成使用的外部契约是 `PurposeRegistry.register(PurposeMeta)`、`LlmRequest.routed`、
`estimateWorstCaseBudget(LlmRequest)`、`LlmCallBudget.maxCalls/maxTokens`、
`LlmBillingContext.player` 和 `withBillingContext`。本补丁没有修改 llmcore 源码或这些接口，
也没有增加构建依赖。实际校对的源码位于 AIjs 的 core/llmcore-mod，库验证使用 llm-core 1.4.4。

`YhLlmCoreBridgeTest` 在真实 core jar 上通过 29 项检查，移除 core jar 后通过 3 项检查。
其中 loopback HTTP fixture 先用旧的 1 次调用预算复现拒绝，再用新预算成功取得 fallback 响应；
不访问外部 provider 或玩家账本。另检查注册时机、幂等性、玩家身份、causal root、长提示词、
路由变更后的重新估算，以及无计费策略时仍拒绝玩家请求。

测试入口为 `dev.xkmc.youkaishomecoming.compat.llmcore.YhLlmCoreBridgeTest`。
