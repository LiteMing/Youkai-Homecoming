# pre1fix：LLM Core 接入、异步草稿交付与修改对比

修复基于 `0.30.0` / `fc5a85081`，单独保存在 `0.30.0pre1fix`。
pre2/barrier 暂存于 `feat/0.30.0-barrier-completion` / `fd823f196`，随后仅回移修复提交。
候选包通过 `-Pll_version=2.7.0+HCDRS_0.30.0pre1fix` 命名，不修改版本字段或发布远端产物。

原实现没有注册 `PurposeMeta`，所以控制台用途列表不显示 `YH_SPELL_GENERATION`；
请求仍可能通过默认路由进入 orchestrator，但计费上下文固定为 1 次调用和 12,000 token。
第一条凭据失败后，后续凭据/provider 尝试会触发 `Causal chain call budget exhausted`，
长能力报告或较大的输出上限也可能触发 token 预算拒绝。

`YhLlmCoreBridge` 现在通过 Forge common setup 注册用途，注册不依赖 AI 开关、服务器 runtime
或首次生成请求。请求时保留幂等补注册。未安装可选库时不阻止 YH 加载。

请求使用 `SharedLlmRuntime.current()`，继承控制台的用途/默认 provider 路由及其他参数。
`spell_ai.maxOutputTokens` 提供输出预算基准，默认 10,000 token；未配置或低于基准的 purpose 输出上限
会在本次请求中提升到基准，更高的显式 purpose 上限保留。这个数值只在 `YHModConfig` 定义默认值。
在完整 system/user 消息和输出上限构建后调用 `LlmOrchestrator.estimateWorstCaseBudget`，
将返回的调用次数/token 上限写入 `LlmBillingContext.player`。预算覆盖所选路由的凭据重试和
provider 回退；请求 ID 同时作为 causal root，独立生成请求各有一个新 ID。
这不会修改 llmcore 的个人预算、计费主体或准入策略。预算 API 缺失或失败时返回错误，
不再吞掉反射异常后发送缺少计费信息的请求。

集成使用的外部契约是 `PurposeRegistry.register(PurposeMeta)`、`LlmRequest.routed` 及其公开构造器、
`getRoutingConfig().resolveOptions(purpose).maxOutputTokens()`、
`estimateWorstCaseBudget(LlmRequest)`、`LlmCallBudget.maxCalls/maxTokens`、
`LlmBillingContext.player` 和 `withBillingContext`。本补丁没有修改 llmcore 源码或这些接口，
也没有增加构建依赖。实际校对的源码位于 AIjs 的 core/llmcore-mod，库验证使用 llm-core 1.4.4。

`YhLlmCoreBridgeTest` 在真实 core jar 上通过 37 项检查，移除 core jar 后通过 3 项检查。
其中 loopback HTTP fixture 先用旧的 1 次调用预算复现拒绝，再用新预算成功取得 fallback 响应；
不访问外部 provider 或玩家账本。另检查注册时机、幂等性、玩家身份、causal root、长提示词、
路由变更后的重新估算，以及无计费策略时仍拒绝玩家请求。新增检查覆盖缺省/低上限提升、较高用途
上限保留、输出上限参与最终计费估算，并检查实际 loopback HTTP 请求的 `max_tokens=10000`。

## AI 返回流程

原返回流程额外运行认证分析器和能力策略，导致 `experimental_fire` 等草稿在写回前被拒绝。
按维护者要求删除只供此入口使用的 `YhSpellDraftValidator`，取消自动写回编辑器及选定卡型二次拦截。
LLM 成功返回的文本不经过新增解析、认证或字段检查，原样送到玩家剪贴板；玩家粘贴后继续使用
现有 Raw JSON 检测器、坏节点抢救和保存/认证入口。打包的系统提示词已与此行为同步。

提交后返回原编辑器，允许继续编辑或关闭。请求完成时，在客户端主线程复制原文并发聊天提醒；
失败只提示错误，不覆盖剪贴板。超过单个网络字符串限额的结果及错误分片发送，避免切断 Unicode
代理对；只在完整组装后交付。请求 ID 在提交、服务端完成和分片回传间保留，关闭界面不丢结果。
断线清理未完成组装和本地对比记录；未实现离线保存/重连投递。

修改请求在客户端保留提交时的原稿字符串快照，聊天提供“查看修改”。对比视图按字段路径显示
新增/删除/修改，忽略空白和对象键顺序，并用不变的数组元素对齐插入/删除；它只在打开视图时计算。
解析不了的结果仍能按原文对照和复制，对比不参与生成准入。原稿/结果均可独立复制，不将差异标记
塞进符卡 JSON，不因玩家之后编辑或请求完成顺序改变比较基准。客户端 `/yhspellai diff <request>`
只用于聊天链接打开本连接中的记录，不发送服务器命令或注册符卡。
