## 玩家流程

提交新建/修改要求后即可关闭请求界面或编辑器。后台使用内置 Skill 生成完整 JSON，调用与
Raw JSON 面板相同的检查器；有问题时，将上一稿和具体字段/坏节点诊断反馈给模型修订。
首次检查通过即交付。`spell_ai.maxRevisions` 默认 2，即首稿后最多再请求两次，范围 0–5；
0 表示交付首稿和检查反馈。所有新的默认配置值只在 `YHModConfig` 定义。

完成后，客户端在主线程复制原文并发送聊天提醒。修订次数耗尽，或已有草稿后 provider 失败，
仍交付最后一份非空草稿，并提供“悬停查看检查反馈”。诊断和 diff 标记不进入剪贴板，也不
把草稿自动编码成删掉坏字段的版本。没有草稿的服务错误只通知失败；空响应不会抹去前一稿。
结果和诊断分别分片，完整组装后一次性交付，保留 Unicode 代理对。

修改继续以提交时的原稿为基准，聊天提供“查看修改”；未完成修订也能查看对比并复制原文。
聊天链接经客户端专用 `SpellAiClientCommandMixin` 将 `yhspellai` 命令交给已有客户端
dispatcher，再由客户端 tick 打开详情页。Minecraft 1.20.1 的点击路径使用
`sendUnsignedCommand`，绕过 Forge 仅接在 `sendCommand` 上的客户端命令处理；此前因此
误发服务器并提示“未知或不完整的命令”。修复只接管 `yhspellai`，不改其他命令的发送路径。
导入改变另一个已有 ID 时继续使用覆盖确认；当前 ID、新 ID、相同内容不新增弹窗，见
[编辑器修复](0.30.0pre1fix-editor.md)。生成、检查和差异展示均不注册、保存或激活符卡。

断线后客户端清理分片和对比记录，服务端停止后续修订且不投递结果。已发出的 provider 请求
仍可能完成，未实现离线保存/重连补投。后台 JSON 解析和修订调度不占用服务器 tick 的同步流程。

## 共用游戏检查逻辑

原 `RawJsonDockPanel` 的解析、Codec 往返和丢字段诊断提取为 `SpellJsonChecker`；
`SpellJsonSalvage` 移到 common definition 包，移除客户端限定。编辑器和 AI 使用同一实现，
没有新增独立 schema、Python 检查器、认证分析器或 EXP/OP 准入策略。

检查内容是 JSON 可读性、Codec 字段诊断和坏节点反馈。抢救保留可用兄弟节点，未知类型抛出的
异常也降级为坏节点；已有 `broken` 占位节点要求修订。`hold_source.on_release` 与激光回调
纳入嵌套诊断路径。旧面板会把部分显式默认值误报为不支持字段，本轮修正普通卡型/EX 标记、
发射器默认参数、反弹参数、当前碰撞默认值及 `size` → `base_scale` 读取别名的判断。

此前导致 `experimental_fire policy EXPERIMENTAL` 拒绝的 `YhSpellDraftValidator` 保持删除。
通过内容检查不等于认证、可装备或实机效果验收；这些仍由玩家正常的认证和使用入口决定，
不以这些策略阻止创意草稿交付。

## 路由与计费

common setup 注册 `YH_SPELL_GENERATION` 的 `PurposeMeta`，无需先启用 AI 或生成请求，控制台
即可发现用途；请求时幂等补注册。沿用 `SharedLlmRuntime.current()` 和控制台 purpose/default
路由。缺少可选库时不影响 YH 加载；计费 API 不兼容时明确报错，不发送未计费请求。

`spell_ai.maxOutputTokens` 默认 10,000 token。缺省/更低的 purpose 上限提升到这个基准，
更高的显式上限保留。完整请求构造后通过实际 runtime 的 `estimateWorstCaseBudget` 计算
凭据重试和 provider fallback 预算，始终使用请求玩家的 PLAYER 身份。

各轮有不同 request ID，共用首轮 ID 作为 causal root。llmcore 的链预算只能取旧值与新值的
较小者，不能在第二轮临时追加，因此首轮发送前即估算首轮及最多 N 次修订的总上限。
修订只保留原始要求、上一稿和最新诊断；后两者受编辑器既有 1,048,576 字符容量约束。
估算模板按最大 UTF-8 字符占用交给同一个核心 API；模板填充不发送给 provider，也不会
预扣虚拟输入。超出编辑器容量的返回稿保持原文交付并停止自动修订。
个人预算和实际结算由 llmcore 照常执行；不改第三方源码、不为修订重置 causal root。
