# pre1fix：真实符卡入场资格

修复基于 `0.30.0` / `fc5a85081`，与 LLM Core 修复分成两个提交。
只改变服务端共用的资格判断及空闲清理，不修改客户端快捷键或公开 `YHStgApi`/KubeJS 契约。

原来的 `hasSpellCard` 只检查 `ISpellItem.isCastReady`；已配置的 `NON_SPELL` 也会通过，
因此 `ClassicControlService` 收到 `TOGGLE_COMBAT` 时允许只有非符的玩家进入。
`GrazeCapability.tick` 又复用了该判断，使错误资格持续存在。

现在入场、普通选卡、自动 Bomb 和非符选取共用主手→副手→背包→Curios 的遍历。
入场与普通符卡选取共用真实符卡判定：排除 `NON_SPELL`、未完成符卡、当局已禁用的卡，
并通过 `SpellItemCost` 检查资源。普通/时符在非战斗时检查 XP、战斗内检查 Bomb；
这里只报价，不提前扣费，实际施放仍走原支付链。

终符有一处必要的上下文差别：原来的 `canActivateLastSpell()` 要求已经进入战斗，
直接以 `findSpellCard()` 非空作为入场资格会挡住只有终符的玩家。
`canAffordCombatEntry` 因此允许冷却结束、没有活动符卡的终符开始下一场战斗；
战斗内仍检查当局使用标记/冷却，实际施放仍要求战斗状态。
不改变创造模式原有的支付豁免，也不改变真实施放的认证校验。

空闲清理改用 `SpellContainer.hasActiveSpellCard`，正在发射的非符不能单独保住入场资格。
真实活动符卡、Boss/PvP 对手仍保留原有的延后清理语义。
`/yhstg combat on` 经 `YHStgApi` 设置的 `combatAdminBypass` 继续豁免资格清理。

`SpellCombatEntryTest` 的 29 项 headless 检查通过，覆盖非符/未完成符卡、主副手/背包优先级、
XP/Bomb 不足、只报价不扣款、战斗中禁用卡、普通/时符可用，以及终符入场/施放/冷却/当局使用状态。
测试使用真实物品选择和支付逻辑；仅提供没有网络的玩家/capability fixture，跳过 mod 入口注册，
补齐正常由 Forge 提供的 capability token 类型名。它不是游戏启动或数据包收发验证。

测试入口为 `dev.xkmc.youkaishomecoming.content.capability.SpellCombatEntryTest`，
使用 YH test runtime classpath 运行。本地限时窄编译通过，日志位于 `build/pre1fix-check/`。
2026-09-13 在维护者要求构建后，正式 `compileJava organizeLang jarJar --offline`
通过，包含重混淆和 refmap 检查，耗时 2m 28s。产物版本为 `2.7.0+HCDRS_0.30.0pre1fix`，
仅通过构建参数覆盖；仓库版本字段未改。

实机验收仍需执行：

- 只有非符：Shift+F 拒绝，并显示已有的“需要可用符卡”提示。
- 非符加普通符、只有可用时符/终符：可以进入；只有未完成符卡不能进入。
- 普通符在战斗中变为不可用：没有 Boss/PvP 对手和活动真实符卡时退出，包括非符仍在发射的情况。
- 伪造 `TOGGLE_COMBAT` 也经过同一服务端检查；Shift+右键和 PvP 自动入场共用资格判断。
- 管理员 `/yhstg combat on` 无卡仍能进入并保持；Curios 中的非符/草稿不能绕过检查。

上游冲突点复核：修改集中于已有的 fork 战斗/支付类；构建、版本、语言和模组入口文件保持原状。
