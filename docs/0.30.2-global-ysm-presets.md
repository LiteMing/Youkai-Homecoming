# 0.30.2：全局 YSM JSON 预设与预览保存

`/yhysm preset` 与 YSM Editor 的命名预设和触发规则改为跨存档共用，保存位置为
`<游戏或服务器实例>/config/youkaishomecoming/ysm_presets.json`。首次使用会创建空文件。
单人使用当前游戏实例的文件；联机使用服务器实例的文件。客户端只保存当前连接的同步副本和编辑草稿，
不会读取本地 JSON 来覆盖远程服务器。

## 在编辑器中制作预设

`/yhysm editor` 默认打开“动作与表情预设”。没有瞄准实体时也可以从目录选择模型制作预设。
“作者轮盘”直接读取模型的 `extra_animation`、子菜单与 `extra_animation_buttons`，按作者顺序
显示可点击条目；配置组显示完整的滑条、单选项与开关，不再要求逐个选择参数。打开配置组保持
当前动作，拖动滑条只更新参数，不重新开始动画。原始动画全集和数值变量放在“高级”中。
这部分只使用 YH 自有界面和已有反射兼容层，不修改 OYSM 轮盘或第三方源码。

以内置 `YH内置/remilia` 为例：

1. 在“作者轮盘”点击“自定义表情1”（`extra6`）。
2. 打开“自定义轮盘表情配置”，选择“自定义表情1”的基础或细节配置组；也可直接切到表情页选择组。
3. 调整嘴型、眼睛、眉毛等控件，左侧即时显示；“脸部视角”、右键平移和滚轮缩放方便检查细节。
4. 填预设 ID，或留空使用自动名称，再点“保存当前预览”。说明和实际应用时长在“预设说明与持续时间”中。
5. 选择已保存预设会立即试播；“另存为新预设”创建副本并保留原定义。
6. “删除预设”与保存、另存为在同一行，删除所选预设及引用它的触发规则；按 Ctrl+S 保存删除。

保存读取当前显示的身体动作和模型运行时的原生数值输入，同时包括生效的绑定与预览覆盖参数。
未改动的默认值和 `0` 也保存；Remilia 共 31 个原生控件，每组自定义表情各有 12 个，完整快照
可以在默认的 32 参数上限内保存。参数缺失、越界、动作不可用或最新修改尚未显示时，拒绝保存
并保留草稿，不能用空值、猜测的零值或截断后的列表冒充完整快照。

预设保存可重放的动作和数值输入，不保存骨骼输出、物理状态、暂停帧或预览视角；应用时从动作
开头播放。模型、纹理仍由绑定指定。没有明确动作的自动走路、飞行和战败状态不能直接捕获为
固定动画，需要先选作者动作。复杂 Molang 控件仍不执行，只提示暂不支持直接调节。

顶栏“保存全部”与 Ctrl+S 在任意标签页保存实际修改过的预设和目标绑定：预设先确认成功，
再保存修改过的绑定；绑定失败后重试只提交绑定。仅浏览模型不产生绑定修改，干净状态下保存
不创建预设，删除后保存也不会恢复为空白预设。星号会说明未保存的是预设、绑定还是两者，
分别收到服务器成功回执后消除；冲突、权限不足和失败保留对应草稿。

表单预设修改仍捕获当前预览；Raw JSON 先校验并保存其配置，不被预览快照覆盖。
“保存当前预览”“另存为新预设”及“更多 → 保存预设库”只保存预设；
“更多 → 保存并绑定”可以显式保存当前模型和目标绑定，即使尚未修改绑定字段。

## 游戏外编辑

文件使用 UTF-8，可由文本编辑器或 agent 直接修改。根对象的 `profiles` 是模型配置数组，
每项沿用 `YsmModelProfile` 的 `format=1` 格式；模型 ID 必须唯一。示例：

```json
{
  "format": 1,
  "profiles": [
    {
      "format": 1,
      "model": "YH内置/remilia",
      "presets": {
        "happy": {
          "description": "表情预设",
          "clip": "extra6",
          "ticks": 20,
          "parameters": { "v.roaming.custom_anim1_mouth_type": 1.0 }
        }
      },
      "triggers": {}
    }
  ]
}
```

`clip` 必须是模型的真实动画名，空字符串可用于纯参数预设。参数只接受有限数值，不执行表达式。
示例是 Remilia 的最小手写预设；编辑器快照会包含所有原生数值输入。其他模型须使用实际公开的变量。
事件触发使用的预设需要 `ticks > 0`。
单模型仍受现有 JSON 长度、预设数量、参数名和参数值边界检查，整个文件拒绝重复模型或未知格式。
Editor 的导出可能附带 `binding`；放入全局库前只取模型配置部分，绑定继续属于当前世界。

运行中修改完成后执行 `/yhysm debug reload`，需要 OP 2，服务器控制台可用。服务器完整校验文件后
替换运行快照，并向所有在线玩家发送重置和逐模型同步包；移除的模型也会从客户端缓存清除。
玩家登录以及 Editor 读取／保存前也重新检查文件，检测到变化时同步所有玩家。
编辑器“重新读取”向服务器发起请求；收到同步时，无未保存修改的模型草稿自动采用新版本，
已有修改的草稿保留并在保存时检查 revision 冲突。
渲染和战斗 tick 使用服务器已接受的快照，不轮询磁盘。

外部编辑不需要维护 revision。服务器按模型内容变化递增会话内 revision，删除也保留并发标识；
旧草稿无法重新覆盖或恢复已删除的模型。未变化模型的 revision 不受其他模型的外部编辑影响。
Editor 保存先落盘，再更新缓存及向客户端确认成功；写入前检查原文件是否又被外部修改。
文件损坏或写入失败会报告错误，保留最后一次有效快照和编辑草稿，避免用空库覆盖原文件。
首次加载文件已经损坏时，预设暂不可用；修复文件并重载即可恢复。

## 旧世界迁移

首次访问旧世界的预设库时，读取该世界的 `data/youkaishomecoming_model_profiles.dat` 并合并到全局 JSON。
未打开的旧世界在下次进入后迁移，不扫描或写入其他玩家存档。

- 全局不存在的模型和预设直接导入；相同内容去重。
- 同模型同 ID 内容不同的旧预设保留为 `<原ID>_migrated_1`、`_migrated_2` 等；过长 ID 截短以保留合法后缀。
- 已有全局触发映射优先；新增旧触发映射跟随导入后的预设 ID。
- 合并成功写入 JSON 后，把原文件改名为 `youkaishomecoming_model_profiles.dat.migrated`，原始字节保留。
  此备份同时标记迁移已完成，重进旧世界不会恢复用户后来删除的全局预设。
- 损坏或超出硬上限的迁移不会部分导入，原文件保留且记录错误；处理旧数据／全局容量后重启世界重试。

实体 UUID/type 的模型绑定、纹理和默认外观仍保存在该世界的 `youkaishomecoming_ysm_overrides.dat`；
实体上正在播放的临时表现仍随实体保存。它们不属于可复用的命名预设库。
