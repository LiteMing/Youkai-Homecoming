# 0.30.2：非符碰撞反馈

本文记录 0.30.2 历史行为。下列非符专用限制已由
[0.30.3 hotfix](0.30.3-spell-permissions-hotfix.md) 的共用检查替代。

0.30.2 放宽非符的碰撞表现边界，让非符可以在弹幕命中实体或方块时播放音效、触发镜头反馈，
同时保留非符作为持续攻击模式的性能和规则边界。

## 规则

- `on_hit_entity` 与 `on_hit_block` 可以存在。
- 回调只接受 `play_sound`、`camera_shake`、`noop`，以及只由这些动作组成的 `conditional` 或
  `sequence`。发射弹幕/激光、生成射手、变量写入、命令、传送、阶段切换和其他战斗状态动作
  会被拒绝。
- `on_expiry` 与 `on_trail` 仍然禁止。
- 碰撞行为必须是 `discard` 或 `expire`。`continue`、反弹和延迟递归不属于普通非符能力。
- 非符主体仍使用现有的当前 Power 单刻发射额度、寿命、速度、原点和分析器性能上限。

碰撞回调有独立的 `nonSpellMaxHookExecutions` 配置，默认在分析窗口内允许 100000 次执行。
这样反馈动作可以随发射模式使用，但不会复用普通符卡的无限回调空间。

## 服务端反馈

声音和镜头提示仍由服务端汇聚后发送。声音音量默认限制为 4.0，示例 JSON 中的 `volume: 30.0`
不会直接传给客户端；镜头强度、时长、半径和每上下文提示数沿用现有反馈上限。

## 回归覆盖

`SpellAnalyzerSelfCheck` 覆盖了 `discard/expire` 碰撞反馈、声音与镜头动作的回调预算，以及回调
中变量写入和嵌套 `fire_danmaku` 的拒绝路径。
