# Spell capability permissions

Spell definitions remain server-authoritative. A definition that passes the
server analyzer may still contain capabilities that the current player cannot
use. The runtime filters those capabilities on the server and continues the
rest of the action list:

| Level | Name | Meaning |
| ---: | --- | --- |
| 0 | `forbid` | The capability is denied by policy. |
| 1 | `base` | Ordinary spell actions. |
| 2 | `hook` | Projectile callbacks such as `on_hit`, `on_trail`, and `on_expiry`. |
| 3 | `experimental` | Experimental emitters and advanced data shapes. |
| 4 | `op` | Operator-only actions. |

`1` and `2` are labels over the existing `ALLOW` policy. The level is applied
per player at cast time. A missing callback is skipped while its projectile is
still emitted. A denied conditional uses its `if_false` branch as the safe
fallback; other denied actions are skipped and later actions continue.

Operators default to level 4. This is a default, not an irrevocable grant:
`/yhspell permission player set <targets> <0..4>` creates a persistent player
override, and `player reset` returns to the normal operator or progression
default. KubeJS can use `YHSpellConfig.setPlayerPermission(player, level)` and
`resetPlayerPermission(player)` for the same persisted override.

With `spellPermissionCardProgression=true` (the default), completing the
existing `spellcard_tier6` advancement grants automatic level 2 and completing
`spellcard_tier12` grants automatic level 3. The advancement state is checked
on the server, so merely holding a high-tier card does not grant the ability.
Set the option to `false` when a server wants scripts or administrators to
grant levels explicitly. Manual player overrides take precedence over both the
automatic progression and the operator default.

Administrator policy commands operate on the global capability policy table:

```text
/yhspell permission list
/yhspell permission get <capability>
/yhspell permission set <capability> <0..4>
/yhspell permission group <group> <0..4>
/yhspell permission player get <targets>
/yhspell permission player set <targets> <0..4>
/yhspell permission player reset <targets>
```

The legacy `/yhspell capability get|set` form remains available. Policy level
0 still denies a capability even to level-4 players; unknown and salvaged
broken nodes remain fail-closed.
