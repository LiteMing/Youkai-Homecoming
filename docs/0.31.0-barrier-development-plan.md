## 1. 已确定的接手决策

1. **结界是 laser 的几何变体。** 复用 laser 的生命周期、准备/展开/收缩、Origin、AimMode、MoverConfig、
   NumberProvider 和发射/同步/清理路径；结界额外保存的是边界几何。停止扩充独立的 BarrierTrajectory、
   MotionState、倒计时和预览运动公式。
2. **结界编辑器达到现有编辑器模式的完成度。** 接入统一工作区、真实预览、属性编辑、Raw JSON、
   草稿和导入/导出流程；画出 Dock 外框、四个输入框和“复制 JSON”不算完成。
3. **英文文案绑定源码，其他语言通过本地化键提供。** 英文无需从 en_us.json 读取编辑器 action 名称和
   字段标签；非英文查对应语言的键，缺失时回退源码英文。不能用 Java 内的中文映射表代替资源键，
   也不能只对 barrier 节点加特殊分支。

旧计划中“每个结界不创建实体”“独立定义保存时长/移动默认值”“独立快照表驱动全部表现”的要求撤销。
具体复用现有 ItemLaserEntity 的变体能力，避免再注册一套平行的运行时系统。
这是仓库内部实现和 pre2 数据格式的调整；不改变公开 YHStgApi/KubeJS 契约。

本轮追加决策：

- 复用关系只体现在数据与实现。结界属性不再显示“激光”类型选择，也不提供结界/激光互转占位按钮。
- 魔法阵和结界的属性、Raw JSON 默认放在右 Dock；已有用户布局须保留，旧默认布局才定向迁移。
- 无交互状态行使用文本，不再伪装成灰色按钮；移除 YSM 弹幕的 Fallback、Model Source 单选占位行。
  必要禁用操作提供原因提示。
- 球面经线数、纬线数和圆弧细分分别保存：线数控制密度，细分控制曲线平滑度。
- 单平面是基本形状；不保留双平面类型。尺寸与共享尺度允许有限非负数，法向偏移允许正负值。
- 结界直接使用符卡的 `ControlsDockPanel`，复用播放、单步、速度、AI、目标和视图设置的行为。
- 自定义表面使用 XYZ 顶点与三角面，支持数值编辑、增删、平面投影拖动和统一撤销；可制作三角形平面和立体星形。
- 结界须提供吸附、推开、隔离的运行时行为，以及每个动作独立的实体筛选；这是延期至 0.31.0 的能力。
  “仅吸附物品和经验”“排斥/隔离玩家通过”是通用能力的使用及验收场景，不要求新增内置预设。
- 顶点和面分别放在可折叠文件夹内，通过下拉选择当前项；仅显示当前项坐标/编号，避免长列表占满面板。
- 三角形平面和立体星形放入独立的自定义预设栏；支持选择、创建、保存和删除，内置起点只读。
- 属性文件夹滚出视口后，在滚动条旁显示标题标签并支持点击跳转；魔法阵复用相同组件。
- 弹幕/激光与结界交互必须覆盖虚拟池、mover、并行 tick、专用同步和渲染路径。当前优先审查这些契约，
  暂停排斥手感的进一步细化。不能以普通世界实体的选择器、碰撞检查或数学检查冒充这项完成。

## 3. Laser 复用契约

### 3.1 一份公共数据与执行路径

| 内容 | 复用位置 | 结界要求 |
|---|---|---|
| 参数及 Codec | FireLaserAction；NumberProvider、OriginConfig、AimMode | 公共字段共用定义、解析、默认语义和校验，不复制一套 barrier 同名字段。 |
| 准备、展开、维持、收缩 | YHBaseLaserEntity.setupTime / percentLoad / percentOpen | 使用同一个相位结果，世界渲染、预览和服务端几何查询不能各算一份。 |
| 运动及初始定位 | MoverConfig；ItemLaserEntity.mover / initializeMoverAtSpawn / setDelayedMover | 支持既有 mover 及组合；不再用 velocity/acceleration/drag 构造第二套轨迹协议。 |
| 生命周期与同步 | laser 的发射、实体同步、拥有者、过期和清屏流程 | 同预设可存在多个实例；实例身份由真实运行实例持有。 |
| 编辑器 | ActionEditorPanel.buildFireLaserRows / buildMoverRows | 抽出有真实消费者的公共行及更新回调；修改一个公共字段不得丢失边界或其他 laser 参数。 |
| 预览 | SpellRuntime → PreviewCardHolder → 实际 laser 预览实例 | 执行到节点才生成，跟随实例时间推进；条件、delay、repeat、回调、切 phase 和重置与运行时一致。 |
| 分析及认证 | SpellAnalyzer、SpecialNodeCounter、现有能力策略 | 复用 laser 的成本/能力分析，并追加几何预算；不得加到无成本白名单来绕过认证。 |

当前规范格式是 `fire_laser` 加可选 `boundary`。界面将有边界的 laser 显示为“Barrier”，
`BarrierAction` 只负责读取 pre2 别名，转换成 `FireLaserAction` 或两个单平面组成的 Sequence，没有独立的执行方法。

Laser 的 lifetime 是维持阶段长度；setupTime 的总生命周期为 prepare + start + lifetime + end。
例如 4/6/20/5 对应总计 35 tick。pre2 BarrierTrajectory 则把准备/展开/收缩包含在 duration 内，
迁移时必须明确转换，不能只把 duration 改名为 lifetime。

现有 FireLaserAction 在 setup 全为 0 时保留 prepareLaser 的默认 setup；这是当前源码行为。
普通 laser 的这条兼容规则已保留。带 boundary 的 action 则明确应用全零 setup，
例如 Koishi 的常驻边界无需经历额外的默认准备期；两种行为均有专项断言。

### 3.2 唯一新增的运行时载荷：边界几何

边界描述局部坐标中的形状和拓扑，不持有 owner、实例 ID、剩余时间、速度、mover 或另一份缩放状态。
预设只是创建边界草稿的快捷入口；导出时携带实际几何，不能依赖客户端有一个服务器从未注册的 ID。

首期几何范围：

- `sphere_volume`：球面边界和球体内部判定。可独立覆盖 `longitude_lines`、`latitude_lines`、`curve_segments`。
  经线/纬线数可为 0，表示不绘制该组线；完整圆弧细分至少为 4。缺省值与上限来自 `YHModConfig`。
- `plane_surface`：一个有限矩形平面，`half_width`、`half_length` 可为 0，`offset` 是沿局部 Y 的有符号偏移，默认 0。
- `box_volume`：盒面边界和体积，任一半尺寸可为 0。
- `polygon_surface`：XYZ 顶点与三角面索引组成的开放表面或封闭多面体，允许凹形状。
  开放表面只做表面查询；封闭网格另做内部判定。拒绝退化/重复三角面、非法索引、非流形边和面自交。
  三角形平面与有 12 个顶点、20 个面的立体星形作为编辑起点。

球面线数只决定经纬线密度。`curve_segments` 独立决定圆弧离散程度；球面 bounds/contains/intersect
继续使用解析几何，不随可视网格精度改变。网格缓存包含三项参数，单个结界的覆盖值可随 JSON 保存。

局部坐标与 laser 的轴向/横向缩放建立明确映射，使用相同的实体位置、朝向和相位变换。
length 控制轴向尺度，thickness 及既有宽度规则控制横向尺度；球形预设须设置等比例的最终尺度。
这份变换同时用于绘制、bounds、contains 和 intersect；查询时转换到局部空间，不能用世界 AABB
代替真实边界。世界层和预览不得各自构造另一套坐标轴或几何公式。

当前局部 Y 为 laser 轴向，X/Z 为横向；polygon 顶点规范写作 `[x,y,z]`，`faces` 保存三个零基顶点索引。
编辑器面属性显示一基顶点编号，并提供 XY/XZ/YZ 投影；拖动保留未显示的第三轴坐标。
维持阶段结界横向比例为 `0.4 × laserType.size × thickness`，轴向比例为 `length`；
两者共同乘以实体的 `percentLoad`。普通 LASER 预设使用 `thickness=2.5`、`length=1` 和向上的 Aim，
因此几何尺寸直接对应方块单位。准备/展开/维持/收缩只读实体相位，不另存缩放时间线。

共享尺度接受有限非负数：横向为零时几何隐藏；轴向为零时无 Y 厚度的表面仍可显示和查询。
普通 laser 保留已有 0.05 尺度下限，结界不再套用该下限。矩形/球面/盒体的零尺寸可以保存；
自定义网格仍需要至少三个顶点和一个非退化面，避免无意义拓扑。

解析必须诊断非法顶点、非有限数、退化三角面和超预算数据。顶点数、面数、尺寸、球面网格及实例预算统一接入
YHModConfig；不在渲染器、实体和编辑器分别硬编码第二份上限。

### 3.3 命中与表现边界

复用 laser 载体不代表可以继续用直线 laser 的中心射线判定不规则结界。
形状对应的精确查询必须单独实现，并共用于服务端判定、预览与内部区域查询。

当前 pre4 的 Koishi/Doremy 视觉预设保持现有玩法：Koishi 推回仍由既有约束负责，Doremy 结界不增加伤害或阻挡。
不能因换成 laser 载体而意外生成可伤人的中心射线。攻击性边界若开放，须先接通其真实几何命中和
现有命中窗口/回调，否则不在编辑器中提供看似生效的攻击选项。

世界线框和内部滤镜读取实际 laser 变体实例。屏幕滤镜保持单层，按稳定规则选取；使用实际摄像机位置，
保留离开时的淡出状态。形状识别不能依赖滤镜开启或第三方渲染模组。
已有材质/滤镜资源属于表现层，不再承担第二份生命周期、移动或几何真值。

### 3.4 实体运行时行为与选择器

结界节点的主要行为入口应为 `[ADV] Runtime`（运行时），允许多个子动作各自选择作用对象，
同一个结界可以同时吸附一类实体、隔离另一类实体。行为、目标筛选、几何作用区域分别配置，
不把“玩家结界”“物品收集结界”等用途固化为类型或预设。

| 行为 | 当前源码语义 | 参数 |
|---|---|---|
| 吸附 | 开放表面吸往面积重心，闭合体积吸往体积重心；物品、经验球均可选择 | 作用范围、每 tick 推力系数 |
| 推开 | 立体从重心向外；表面仅对接近运动施力，穿过后继续远离不追加推力 | 表面正反面独立强度；法线、局部 ±XYZ 或禁用 |
| 隔离 | 普通移动以实体碰撞箱连续检测，不允许从任一侧穿面；强度为零仍阻挡 | 推力系数只控制接触后额外推开，不决定墙是否有效 |

优先复用原版 `EntitySelectorParser` 的语法解析及筛选条件，不通过 `run_command` 间接实现物理行为。
每个动作允许包含选择器列表（并集）和排除列表；例如物品与经验球用两条选择器，
不能写成一个选择器中的两个正向 `type=` 条件。实体类型标签可用于作者自行组织类型集合。
`type`、`tag`、`team`、名称和取反等原版条件应保留原有含义；未支持的条件须明确诊断，不能静默忽略。

选择器的候选集限定在同维度的结界作用范围；最终接触、吸附距离和穿越判断使用球面、单平面、盒体、
XYZ 网格的真实几何。原版 `distance` 和包围盒选择不能替代不规则结界的精确查询。
选择器解析缓存、局部实体查询及 Analyzer 成本/能力策略已接线。
每条 `barrier_behavior` 规则只能在真实 boundary 的 `on_trail` 上下文刷新，规则在刷新间隔内保持，
响应逐 tick 生效。正延迟回调不允许在之后偷偷改写活动规则；静态分析与运行时约束一致。
默认原点为几何重心，原版 `x/y/z` 覆盖值仍是绝对坐标，`@s` 是该结界的施法来源。
预览只筛选隔离场景内的实体，不得操作当前客户端世界中的真实实体；依赖服务端状态的条件须说明预览限制。

`onTrail` 提供存续期间的共享调度及子动作上下文；独立编辑器的 Runtime 文件夹可添加、选择、删除规则，
复杂嵌套分支使用符卡节点编辑器。共享控制栏提供预览实体类型及初始位置、速度；重置/定位恢复这些初值。
该测试对象验证运动响应，不模拟原版玩家的完整重力、摩擦或网络输入。
`onExpiry` 有独立用途，可保留为次要分支；无实际命中语义的结界不重新开放激光实体/方块命中入口。
常规移动的穿越检测不能只检查当前端点，须覆盖高速跨面、移动/缩放边界及状态失效后的释放。

`BarrierPhysics` 对球/椭球使用解析检测；网格连续 SAT 覆盖高速移动、实体尺寸和有限表面边缘。
相同几何共享不可变的局部三角面、重心和包围盒树；实例移动时只重建变换后的面数据并更新树的包围盒，
不重复排序拓扑。树用于最近表面及扫掠查询，结果与逐面检测对照。物理精度不依赖可视经纬线数。

当前限制必须保留：移动/缩放结界用前后变换做相对扫掠，旋转路径是直线近似，不能声称任意高速旋转精确；
复杂交角采用有限次滑动与保守停止；`Entity.move` 钩子不覆盖任意 `setPos`/瞬移。
平面软推力与原版落地副作用的发生顺序仍未完成验证。归档中保存了提前调整比较基准的改动及
垂直滑动精度用例；生产窄编译通过，但最新测试类编译失败，尚未执行这些新增用例。
不能把移动结束后标志正确等同于落地伤害已正确，也不能将归档改动当成已验证修复。
普通世界实体、原版玩家移动包和移动载具的接线尚需实机验证。

普通规则明确排除 `SimplifiedProjectile`，包括加入世界的同类弹幕。对它们直接改速度会被 mover 覆盖，
且不能正确同步；世界查询也看不到虚拟池。预览不能把这类弹幕伪装成普通实体测试对象。
原版选择器解析器本身仍可复用于专用弹幕候选集，但候选来源、快照与归属须按下一节实现。

pre4 和此前 4616 项检查均不覆盖本节新增规则。源码接线、窄检查与真实游戏验收分别记录。

### 3.5 虚拟弹幕/激光交互与预计算

本节记录第 5 项需求的源码审查及接入约束，效果类型暂不扩张。当前工程推进假设是优先同一次施法，
跨实例交互必须显式选择；这不是把跨符卡交互判定为不可实现，也不是用户已经确认的范围缩减。

已确认的真实路径（Java 路径相对 `src/main/java/`）：

| 环节 | 当前路径 | 对结界交互的约束 |
|---|---|---|
| 服务端虚拟池 | `dev/xkmc/youkaishomecoming/content/entity/danmaku/VirtualDanmakuHolder` | 弹幕可不加入世界索引，`Level.getEntities` 和原版 `@e` 世界查询不能遍历它们。不能为了选择器方便把上万弹幕恢复为普通世界实体。 |
| 批量 tick | `dev/xkmc/fastprojectileapi/entity/ParallelTicker` | 按准备、计划移动、裁剪、收集碰撞、应用移动、执行效果分阶段；跨弹幕数据必须在主线程形成不可变快照，worker 不得读写世界或共享规则表。 |
| 弹幕运动 | `BaseProjectile.planMove/applyMove`、`TargetPosMover.move` | 直接应用 `TickData` 与 `setPos`，绕过 `Entity.move`；命中后的改轨需保持、重基或明确脱离 mover，不能只写一次 velocity。 |
| 激光几何 | `BaseLaser.collectCollisionInput`、`YHBaseLaserEntity.effectiveLength` | anchor 的小碰撞箱不代表整束激光。须查询整段光束及半径；接触结果同时用于伤害、擦弹、回调端点和可见长度。 |
| 客户端 | `ClientDanmakuCache`、`DanmakuBounceSyncPacket` | 数千弹幕可整 tick 并行运行；普通实体速度包覆盖不到虚拟对象。现有单弹 bounce 包不能直接变成上万弹每 tick 一个包。 |
| 渲染 | `ClientDanmakuCache.renderAll`、`ItemLaserRenderer`、YSM bridge | 保留 billboard/批量绘制、连续 laser 网格和 YSM 软依赖路径；渲染读取同步结果，不运行世界筛选或权威碰撞。 |

同一个 Boss、proxy、`spellId` 或同一个容器并不等于同一次施法。owner 还参与跟随、伤害归属与发包跟踪，
不能挪用它作为交互分组。专用路径需要记录施法实例、发射节点/批次和子发射器继承关系；
旧阶段仍存活的弹幕、并发子符卡、同 ID 重施法必须可区分。生命周期结束后不能让新施法复用旧的接触记录。

“烘焙”分为三层，只有可证明的部分进入缓存：

| 层级 | 可预计算的内容 | 失效与限制 |
|---|---|---|
| 几何 | 网格拓扑、面积/体积重心、查询加速树、解析形状数据 | 已接入普通实体物理；位置/旋转/缩放属于每实例 frame，不进入共享缓存。不是完整弹幕交互烘焙。 |
| 发射关系 | 固定发射组与结界的候选关系、局部边界及稳定筛选条件 | 需要专用编译器和真实施法上下文；空间范围、规则或分组改变时重算。不能仅凭相同 spellId 认定可缓存。 |
| 轨迹与接触事件 | 输入已固定的运动片段、命中时刻或激光裁剪曲线 | 仅当随机采样结果、时间线、相对变换和所有相关参数确定；追踪玩家、实时条件、外部干预、改轨/反弹会让后续片段失效。 |

两者处于同一个持续跟随的刚体坐标系时，共同平移/旋转可以消去；从 Boss 发射后独立飞行的弹幕并不满足这个条件。
发射时已固定的随机参数可做实例级编译；持续读随机数、目标或世界的表达式不能在编辑器预跑中消耗实际随机序列。
只用录制预览的采样点近似轨迹会漏掉高速穿越，不作为权威接触判断。

不默认存储“所有弹幕每一 tick 的 XYZ”。例如 10,000 弹幕 × 600 tick × 3 个 float，
仅位置就有 72,000,000 字节，尚未包含速度、规则与分支。优先共享轨迹段/发射批次、缓存接触事件，
未确定的片段回到同一套几何查询。结果缓存必须包含几何/规则/轨迹修订号与施法实例，改轨后不得复用旧结果。

实时路径按下列顺序接入，不能全世界逐弹对所有结界做笛卡尔积：

1. 使用虚拟池/施法实例的候选集，在主线程解析与编译选择器；固定类型/分组可在生成时筛选。
   原版 `predicate`、scores、NBT 等依赖活实体的条件必须在主线程求值后快照；不能在 worker 直接调用它们。
   带 `sort`/`limit` 的规则按该规则的候选集合批量求值，不能给每颗弹幕分别执行一次随机选择。
2. 粗筛结界包围盒、弹幕移动线段/光束的扫掠范围；结界数少时只扫小型实例列表，密集场景再使用空间分区。
   网格细筛复用局部拓扑树，球/盒/平面用其对应几何。跨符卡与同符卡可以共用窄查询，差别主要是候选来源及缓存有效性。
3. 在 `collectCollisionInput` 之前完成会影响本 tick 轨迹/光束长度的裁剪；之后才执行伤害、擦弹和回调，
   防止结界后方已经受到伤害。副作用由主线程统一应用，确定同一时刻多个接触的顺序；回调生成物进入下一次安全批次。
4. 保留真实 block/entity 接触的类型。结界接触不能伪装成 `BlockHitResult` 来复用代码，否则会错误触发方块命中动作。
   激光的源点跟随和光束接触分别处理，不得为了截断光束而把 anchor 移到结界面或直接覆盖 mover。
5. 确定的片段可给客户端共享紧凑计划；动态结果按跟踪对象、tick 和施法实例批量同步。
   每条结果须能定位虚拟弹幕并排除过期/重排数据；客户端不见另一个结界时也不能自行反推伤害状态。
   预览复用同一候选与几何路径，不能只改变画出来的长度。

开销主要由实际候选对数、网格面数、变化频率、复杂筛选和同步量决定。空间分区通常能减少候选，
但所有结界与弹幕都重叠时仍会退化为全对数；预计算也会有首次编译和缓存重建成本。
普通实体的 `maxRuntimeTargets` 只限制额外推力，不能当作上万弹幕交互的预算，也不能达到上限后让隔离随机漏弹。
专用路径应分别配置候选对/细筛、每 tick 响应、缓存内存/片段与同步字节预算；超限在 Analyzer/运行时显式诊断，
拒绝启用超出预算的新交互或终止对应受管理的施法，不静默跳过已经承诺的阻挡。所有可调预算进入 `YHModConfig`。

性能验收必须区分：无交互、无空间重叠、同实例确定轨迹、追踪/移动结界、跨 owner 以及最坏全重叠；
分别覆盖 1,000 / 10,000 / 20,000 弹幕、普通激光/挂载激光、球/平面/多面体和 YSM/Oculus 有无组合。
记录主线程和 worker 阶段耗时、候选/细筛数量、分配与缓存、每 tick 包数/字节及客户端绘制成本。
数学查询的并行一致性检查不等于这些场景已经跑通；当前没有上万弹幕结界交互的实机性能数据。

### 3.6 迁移和删除范围

- 新格式只写共享 laser 字段及边界数据；旧 pre2 的 duration/scale/motion/trajectory 在读取边界一次迁移。
- 可以等价转换的旧值转换为公共参数/mover；无法等价转换的组合返回带字段路径的诊断，
  不静默忽略、不保留第二套执行器兜底。
- 替换 BarrierTrajectory 和 BarrierManager.MotionState；最终移除旧 BarrierInstance/
  BarrierStateToClient/BarrierClientState 运行链，使用 laser 的实例及同步。
- 内部进出事件如继续保留，只观察实际活动实例；移除、过期、换维度和断线都需覆盖。
  不在本次重构中冻结为公开 API。
- 更新注册和内置符卡后检查零消费者类/方法；不得留下“旧实现仍在被某个入口调用”的双路径。
- 普通 fire_laser 的既有数据和行为保持可读取、可运行；内部破坏性变更写入分支说明和后续提交说明。

读取迁移已限定为已知 pre2 预设和 `TRAJECTORY`：`duration` 减去 prepare/start/end 得到 laser 的
维持时间；旧的速度、加速度和阻尼递推转换为标准 `FixedDir + Translate` mover。
迁移保留 pre2 Doremy 的几何范围：生成两个 16/16、offset 为 ±4 的单平面；
新的默认符卡另用与其激光阵列一致的两个 46/46、offset 为 ±2 的单平面。
pre2 的 FOLLOW 模式曾只采样一次实体脚底，不能无提示地改成真正跟随；读取时返回字段诊断，
要求明确选择 origin/mover。准备期显示比例统一采用 laser 的 0.1，取代旧原型的 0.05，这是可见迁移差异。

pre3 的任意 `parallel_planes` 不自动拆分：两个发射 action 可能改变随机参数、mover 和回调的采样语义。
读取时给出明确替代方式：使用两个 `plane_surface`，offset 分别为 `-separation/2` 与 `+separation/2`。
已知 pre2 Doremy 预设按上述确定值迁移；独立结界编辑器无法同时编辑迁移后的 Sequence，会提示先在符卡编辑器导入并选择一个面。

旧 polygon 的 `[x,z]` 顶点按 y=0 读取；未提供 faces 的有序平面轮廓自动三角化，支持凹轮廓与斜平面。
旧 `half_height` 拉伸转成明确的 XYZ 顶点与上下/侧面，导出只写 vertices/faces；不能同时提供 faces 与 half_height。
Raw JSON 的未知字段检查只允许这些经 Codec 验证的迁移，不吞掉拼写错误或其他未知字段。

非法的已提供字段必须返回 Codec 错误，不能退回默认值。`boundary=null`、错误几何、无效可选
laser 字段及含错误 action 的 phase 列表均有回归检查；不能把被拒绝的边界解码成普通伤害激光。
这也意味着旧格式中曾被宽松解码器忽略的错误值现在会被诊断，合法普通 laser 的缺省字段仍兼容。
旧的私有快照包、缓存及 `BarrierPresenceEvent` 已移除；不保留 pre2 混版联网保证，客户端和服务端须同步更新。
公开 `YHStgApi`、KubeJS 事件、第三方反射签名和第三方源码未改。

## 4. 编辑器完成标准

采用 SpellPreviewScreen 现有模式工作区和 Dock 交互。结界模式编辑“公共发射/运动参数 + 边界草稿”，
公共参数走现有行编辑器；几何面板只负责边界。独立入口与符卡节点的高级编辑入口使用同一个草稿模型。

| 用户操作 | 必须得到的结果 |
|---|---|
| 新建/选预设 | sphere、plane、box、polygon 可作为草稿起点；三角形和立体星形在独立“自定义预设”栏选择，新建/保存/删除沿用 ID 与草稿交互；切换可撤销。 |
| 编辑公共属性 | lifetime、setup、Origin、AimMode、mover、缩放和适用的公共表现参数使用已有控件；切换 mover、改速度等不重置其他字段。 |
| 编辑边界 | 尺寸、法向偏移、独立经纬线数/圆弧细分有标签和校验；顶点/面分别折叠，下拉切换仅显示当前 XYZ/编号。图形与数值选择同步；细分面增加顶点；删点删除关联面并重排编号。 |
| 预览 | 使用真实 3D 视口和共用 ControlsDockPanel；可旋转/缩放、切正交/透视、播放/暂停/重置/定位时间，并看到展开、移动和收缩。 |
| 在符卡中预览 | 未触发的结界不显示；同预设的多个实例独立存在；目标移动、垂直轨迹和非零 drag 的结果与运行时一致。 |
| Dock 操作 | 每个面板 dockId 唯一；属性与 Raw JSON 默认在右列，控制栏在底部。保存比例和活跃 Tab，隐藏页释放焦点；菜单可跨 Dock 展开，窄控制栏可滚动。 |
| 文件夹跳转 | 屏外文件夹的标题缩为侧边标签，完整标题可悬停查看，点击定位滚动；标签很多时支持翻页和滚轮。魔法阵使用相同组件。 |
| Raw JSON | 可完整查看、编辑、导入和应用；Codec 报错显示字段诊断，错误输入不覆盖上一份有效草稿。 |
| 撤销/返回 | 属性、顶点、预设和 JSON 操作进入统一撤销/重做；返回符卡保留来源节点和选中状态，脏草稿走既有确认流程。 |
| 导出/应用 | 边界导出可重新导入；符卡导出经当前 Codec → Analyzer → 认证/同步链路；应用后再次打开值一致。 |
| 性能反馈 | 展示实际几何顶点/面/边数、开放或封闭状态和对应预算；不显示未经计算的性能估算。 |

第一批移除旧 BarrierEditorScreen 的简化示意图、Screen 全局挂控件和单行 JSON 实现，
复用现有模式的布局、滚动、事件路由及草稿约定。不能靠重新排版旧四个字段替代这些完成标准。

Dock 保存使用面板 ID 记录活跃 Tab，兼容旧索引并在过滤失效面板前映射；单个损坏分支不抹掉有效兄弟分支。
保存先写临时文件再替换，保留 `.bak`；主文件损坏时读取备份。无可恢复数据时拒绝覆盖损坏原文件。
切模式、窗口 resize 和重建均保留当前布局，重置只清对应模式；移除加载时强行搬走 Raw JSON 的旧逻辑。
魔法阵与结界只迁移匹配旧默认拓扑的布局，并保留原比例和可用 Tab；自定义布局不自动重排。

结界模式有六个 Dock：左侧预设与预览/几何，右侧属性与 Raw JSON，底部共享控制栏。
预设位于游戏目录 `youkaishomecoming/spell_editor/barrier_presets/<namespace>/<path>.json`，
保存完整且通过 Codec 的结界 action。内置起点只读，自定义预设支持原子保存和 `.bak`，删除保留 `.deleted`；
拒绝重复 ID、目录跳转和覆盖内置。切换前处理未保存草稿，不让无效 Raw JSON 覆盖已有预设。

## 5. 本地化接线规则

编辑器显示值采用“稳定 key + 源码英文回退”的统一入口：

- 英文模式直接返回源码英文，不受资源包中 en_us 编辑器文案影响。
- 非英文模式先读取对应语言 key；缺失回退同一份源码英文，不把 key 当作用户可见文本。
- 游戏语言不是中文时也必须可以翻译；不能用 isChinese() 作为“是否查翻译”的判断。
- 编辑器主动切换 EN/中文时覆盖游戏语言；未主动覆盖时跟随实际语言及资源重载。
- action 名称、字段、枚举选项、按钮、提示及校验错误都要核对；不再为 barrier 单独维护中文特例。

键范围：

| 范围 | 约定 |
|---|---|
| action 名称 | 保持 youkaishomecoming.spell_editor.action.<type> 及已有别名映射；英文由源码提供。 |
| action 公共字段/枚举 | 复用或补齐 action 命名空间下的稳定键；laser 与 barrier 共用相同字段键。 |
| 结界模式专属文本 | 使用 spell_editor 命名空间下的结界编辑器键；不把中文文字直接写进 Java 映射表。 |
| 普通运行时/配置文本 | 仍按 AGENTS.md 的中文分片 + 英文 en_us.json 双来源维护。 |

中文新增键先进入 src/test/resources/youkaishomecoming/lang/zh_cn 分片，再由 organizeLang
生成运行时 zh_cn.json。编辑器 action 的英文硬编码决策不改变普通运行时/配置文本的双语维护规则。

## 7. 首批回归场景

1. 普通 laser 和结界使用同一组 4/6/20/5 setup 与同一 mover，在相同实例 age 上比较位置、
   朝向、展开比例和结束 tick；换成组合 mover、非零阻尼后仍保持一致。
2. delay 后生成、条件未满足、repeat 同预设、phase 切换、重放/重置各一个场景；
   比较服务端与预览的实例数量和创建/销毁时刻。
3. 将一个准备/展开/收缩均非零的草稿修改 mover 参数，再切编辑模式、导出、重新导入，
   检查未编辑字段、边界顶点和选中状态。
4. 转动/平移/非等比缩放边界，对内部点、外部点、穿越线段及擦边线段核对真实几何；
   单平面和 XYZ 三角面覆盖共面、穿越与零轴向尺度情况，立体星形覆盖凹陷附近的内外点。
5. 在结界中换维度、退出重进，以及相同世界中清屏/结束符卡；旧实例和内部滤镜不残留。
6. 英文、中文、非中文翻译覆盖和缺键回退；逐个检查名称、字段、枚举、按钮与错误提示。
7. 球面分别调整经线、纬线和圆弧细分，保存重开；确认线密度与平滑度独立，关闭一组线不影响另一组。
8. 从三角形起步增删点/面并修改 XYZ，在三个投影中拖动、撤销与重做；从立体星形修改尖顶并导出重开。
9. 魔法阵和结界拖动 Dock、切活跃 Tab、调整比例、resize、切模式再返回；检查自定义布局保持与 Raw JSON 位置。
10. 大量顶点仅显示当前选择项；多个屏外文件夹标签可翻页跳转。预设新建、覆盖、删除、重启重开与坏草稿保护。
11. 虚拟/世界生成弹幕都不被普通实体规则误改；同一 owner 下不同施法、子发射器与旧阶段弹幕的专用交互归属分别验证。
12. 第 3.5 节性能矩阵通过后，才将弹幕与激光交互从源码实现标记为实机验收完成。
