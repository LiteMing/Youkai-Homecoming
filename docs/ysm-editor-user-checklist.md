# YSM Editor 操作与验收 checklist（0.28.0）

实现入口：`/yhysm editor`，或现有 Editor 顶栏模式按钮依次切换“符卡 → 魔法阵 → YSM”。
本页不是正式发布声明；文末未勾选项必须在游戏内验证，编译通过不能替代它们。

当前包：`build/libs/youkaishomecoming-2.7.0+HCDRS_0.28.0.jar`。
按维护者要求在功能提交后 bump 0.28.0；版本号不是实机验收通过的证明。
只生成本地包，未替换现有整合包 JAR 或玩家存档。

## 先按使用场景操作

- [ ] 打开“目标与场景 → 使用场景”，选择更换模型、弹幕战开启、切换符卡、近战命中或切换现有模型预设。
- [ ] 选择 UUID/type 或读取瞄准实体；读取已有绑定会载入对应模型。没有绑定时不擅自选目录中的第一个模型。
- [ ] 更换模型：选模型及纹理，点“保存绑定”，无需创建动画预设。
- [ ] 配置事件：选已有预设，或点“配置该场景的动作与表情”。新建时自动填场景预设 ID；编辑后“暂存并返回使用场景”同时建立预设和映射，再“保存并绑定”。
- [ ] 切换当前模型预设：读取实体绑定，选已保存预设，点“在选定实体上播放”。不替换模型、不改自动规则。
- [ ] “模型素材与参数工具”作为辅助标签使用。已有停靠布局保留；顶部“使用场景”直接返回主流程。

## 符卡预览和 YSM 动作节点

- [ ] 先保存符卡草稿，从“更多 → 选择符卡预览模型”进入 YSM 工作区。明确选择模型后点顶栏“用于符卡预览”；只绑定本地假施法者，不替真实实体换模型。预设草稿需先“仅保存预设”。
- [ ] 未选择预览模型、也未执行设置模型节点时，不渲染 YSM 施法者，保留原标记和法阵。正交、透视与截图应一致。
- [ ] 新增 `ysm_render` 节点，按操作下拉选择设置模型、应用已保存预设、播放原生动画、调整表情参数、停止手动动作和表情或恢复原有模型。只显示相应字段。
- [ ] 播放时间线，核对模型设置后才出现；预设、表情参数、到期和清除均可见。重置时间线后不能残留上次播放的动作/表情。
- [ ] 普通 phase 切换不自动算“切换符卡”；该 phase 特定表现可在进入动作放“应用已保存预设”节点。真正换符卡由自动场景触发。
- [ ] “更多 → 移除符卡预览模型”移除本地模型选择；后续设置模型节点仍可按时间线重新显示模型。

破坏性调整：旧 `ysm_render` 的 `animation/clear/clear_target` 设计不再支持，节点必须带 `operation`。
无下游兼容层。字段与迁移说明见 `docs-dev/yhmodel-script-api.md`。

## 开始前

- 建议使用整合包和世界的测试副本。客户端、服务端必须安装同一份 YH 开发构建；不要让两个版本的 YH JAR 同时留在 `mods`。
- 当前模型适配基线：`openysm-forge-2.6.6.2-HCD-0.1.2.jar`。没有宣称支持官方 `ysm` 3.0-dev。
- 预览与查看目录不需要 OP；保存绑定、共享预设、应用真实实体需要 OP 2。
- 暂停行为与符卡/魔法阵 Editor 相同：单人世界暂停，联机和已开放局域网的世界不暂停。本地预览有独立时钟。
- 首期真实控制对象是 YH 妖怪/Boss 和发射器；不是玩家/TLM 女仆的统一动作控制器。
- 目录和模型来自当前客户端，服务器只保存配置与表现请求；其他观察者也需要对应模型资产。

## 0. 先确认预览与原有布局

- [ ] 左侧拖拽向上/向下旋转模型，并在几档缩放下观察头部、上半身。模型处于视窗内的部分不应被背景平面切掉；真正超出视窗边界仍正常裁切。
- [ ] 单人打开 Editor 后周围生物与世界暂停，模型预览仍可单独播放/暂停。不要用局域网或多人世界判断单人暂停是否失效。
- [ ] 先调整魔法阵的停靠比例/标签位置，再切到 YSM、切回、缩放窗口或切换全屏、关闭重开；魔法阵和符卡布局各自保留。不要点“重置布局”。
- [ ] 有未保存修改时切模式，取消应回到原界面；确认放弃后应进入目标模式，不应留在确认弹窗。

本轮没有修改字体或 Editor 的 GUI 缩放策略。判断文字清晰度请看游戏窗口或截图原图。

## 1. 绑定模型与顶栏保存

- [ ] 开界面前瞄准一个 YH 妖怪，运行 `/yhysm editor`。
- [ ] 右侧“设置内容”下拉选择“实体绑定”；点击“使用打开编辑器前瞄准的实体”，或手填目标。
- [ ] “应用范围”选单个 UUID 或同一 type。type 使用原生注册表/命令补全，不再限制 YH 命名空间；UUID 候选按距离排序，第一行标注实体类型和距离，第二行显示完整 UUID，选中只填 UUID。
- [ ] 中间“浏览内容 → 模型”，从“文件夹”逐层进入目录，再输入名称筛选并选择模型。候选旁有独立小窗口预览（窗口空间不足时不显示）。也可在右侧手填实际模型 ID，点“编辑此模型”。**ID 以目录为准，不能从显示标签猜。**
- [ ] 选择纹理；Tab 补全，或点击“使用模型默认纹理”。
- [ ] 顶栏“仅保存绑定”只保存 UUID/type 的模型和纹理；等提示“实体绑定已保存”。
- [ ] 配好预设后点顶栏“保存并绑定”，等提示“预设已保存，模型已绑定到选定目标”。它先保存预设，收到成功确认后再绑定；若第二步失败，会明确提示预设已保存、绑定未确认，可检查后重试“仅保存绑定”。
- [ ] 顶栏“仅保存预设”/Ctrl+S **不修改实体绑定**。不要把“正在编辑模型”或“模型预设已保存”当成绑定成功。
- [ ] 关闭界面，确认真实实体变为目标模型。

绑定优先级：UUID > type > 资源默认。禁用 UUID 会屏蔽 type；移除 UUID 覆盖才会重新使用下层。
`ysm_render` 的“设置模型”是临时覆盖，不保存 UUID/type 绑定；“恢复原有模型”清除该覆盖。禁用绑定时不会强行启用渲染。
修改永久绑定不会覆盖一个仍有效的符卡临时模型，排查时用 `/yhysm inspect`。

“不使用 YSM 模型”不删除模型资产；“移除自定义绑定”不删除下层绑定。
UUID set/off 需要服务端当前加载了该实体；已知但卸载的 UUID 仍可以 unset。

## 2. 分类查找动作与表情

- [ ] “浏览内容”下拉切到“身体动作”，用文件夹按动画名前缀逐层查找；`extra1/extra2` 归入 `extra`，`.`/`_`/`/` 前缀形成层级。这里只按名称分组，不冒充来源 JSON 文件；选择后仍使用完整原生动画名。
- [ ] 切到“转盘动作与菜单”，筛选并选择作者条目，再点击其实际具备的预览/配置/子菜单按钮。修改筛选文字后不能继续操作旧条目。
- [ ] 切到“表情与外观参数”，先选分类，再通过输入框＋下拉选择一个参数。只显示这个参数的开关、数值选项或数值输入，不平铺全部控件。
- [ ] 输入后按 Tab/下方向键展开匹配，点击箭头显示全部；方向键/Tab 移动、Enter 选择、Esc 收起，滚轮滚动候选。菜单跨到相邻 dock 时仍能点击，不应误操作下层面板。
- [ ] 左侧拖拽旋转、滚轮缩放；检查表情。右侧预设页可查看加入的参数名和值。
- [ ] 使用“停止预览”清除本地显式覆盖；“重置预览”丢弃旧假实体与模型运行状态。

仅有配置入口的 `extra1` 不是自动可播放动画；子菜单也不是片段。
普通表情页隐藏无法直接操作的复杂 Molang/未知控件；原始表达式仅保留在指令诊断目录，不执行。
模型控制范围内的合法数字才会应用；高级 raw 输入允许 `v.name` / `v.roaming.name`，不支持函数/数组/任意脚本。

已核对的外部资产例子：整合包 `config/yes_steve_model/custom/touhou/蕾米莉亚/ysm.json`：

| 能力 | 这份资产的标识 |
| --- | --- |
| 展示威严 | `extra5` |
| 嘴巴微笑 | `v.roaming.mouth = 2` |
| 腮红 | `v.roaming.saihong = 1` |
| 生气特效 | `v.ysmemoji = 1` |

这些不是通用默认值，也不等于内置 remilia 必然拥有同一组控件。其他模型应重新查目录。

## 3. 保存可复用预设

- [ ] 右侧切到“动作与表情预设”。填稳定 ID，例如 `happy`；ID 使用小写字母、数字、`_ . : / -`。
- [ ] 填说明、原生 clip、持续 tick。`20 tick = 1 秒`；`0 = 保持到清除/实体卸载`。空 clip 可保存纯表情组合。
- [ ] 从参数下拉选一项查看/修改数值，或手输变量名，点“加入预设并预览”；“移出当前预设”只移除选中的参数。手输变量名后按钮应立即可用。
- [ ] 点击“暂存此预设”。这一步只是本地暂存，方便继续编辑下一个预设和触发规则。
- [ ] 顶部“仅保存预设”/Ctrl+S 保存定义；需要绑定当前 UUID/type 时用“保存并绑定”。均等待对应确认。未起 ID 的脏字段会报错，不会被丢弃。
- [ ] “编辑预设”下拉直接切换。合法的未暂存字段会先暂存；字段无效时保留当前内容，不能悄悄切走。
- [ ] 切换模式、关闭并重开，确认已保存定义仍在。

预设按模型隔离。修改 ID 相当于另存一个预设，不是自动改名已有引用。
“删除此预设及其触发规则”先删本地，保存后才同步到服务端。
原生按钮只是客户端目录；脚本枚举的是这里**保存到服务器的 YH 预设**。

## 4. 配置自动触发

- [ ] 右侧切到“自动触发”，选择“何时触发”及“使用哪个预设”。选择即更新草稿，不需要另点“设置”；“不设置”移除此映射。
- [ ] 用“预览：所选状态”查看效果；它清除本地显式试播以显示自动规则，不给真实实体施加效果。
- [ ] 顶部“保存并绑定”让选定 UUID/type 使用这个模型及规则；已有正确绑定时也可“仅保存预设”。等待确认后关闭界面观察真实触发。

| 触发 | 行为 |
| --- | --- |
| idle / walk / fly | 服务端采样持续状态；只在状态变化时更新同步。映射持续到退出，不用预设 ticks 提前结束 |
| enter_combat | 服务端真正开始 tick 符卡时；单纯锁定近战目标不触发，持续弹幕战不重播 |
| spell_switch | 弹幕战中开始另一张符卡的第一次 tick；普通 phase 和并行子图不冒充换卡 |
| melee_attack | 妖怪 `doHurtTarget` 返回成功后；挥空不触发，连续命中重播 |
| hurt | 服务端未取消且有效伤害量大于 0 的伤害事件；连续命中采用“最新命中重播并重新计时” |
| defeat / falling / prone | 既有 beaten 三相位的投影。prone 保持到权威状态结束；动画结束不解除战败，不改变 AI/重力/碰撞箱 |

事件映射必须使用 `ticks > 0` 的预设。状态映射忽略 preset ticks，跟随状态寿命。
“falling”在这里特指战败下坠，不是所有普通跳跃/失足的判定。
发射器执行数据符卡时也可发出进入/切换信号；近战场景只接妖怪的真实攻击入口。

身体优先级：战败 > 显式命令/脚本/节点/Editor > 旧发射器动画提示 > 受伤 > 近战命中 > 换卡 > 弹幕战开启 > 日常。
表情逐参数按相同优先级合成；未冲突的显式参数可继续生效。
战败期间不叠加日常/受伤层。战败没有映射、或映射片段缺失时，继续原 `special=...` 回退链。

## 5. Raw JSON 与备份

- [ ] 点击 `Raw JSON` 标签或同名顶栏按钮。内容应是当前模型的 `format=1` 预设及 triggers；进入时先收集合法预设字段，未起 ID 的字段需先命名或还原。
- [ ] 修改一段说明或触发项，点“应用到草稿”；表单与预览应更新，然后顶部保存才写入世界。Ctrl+S 也会先校验并应用 Raw JSON。
- [ ] 输入不完整 JSON 后保存：应保留原文并拒绝保存。切 tab、缩放窗口不得丢字；复制/粘贴、Ctrl+Z/Ctrl+Y 可用。
- [ ] 修改 JSON 后再改表单，应拒绝用旧 JSON 覆盖新表单。先导出备份，再点“从表单重新生成”并手动合并。
- [ ] “导出 JSON”复制到剪贴板；存在未应用 Raw JSON 时导出原文（可能无效，但不丢修改）。导入只改本地草稿，且模型 ID 必须一致。

此页不是原生 `ysm.json` 编辑器，也不修改第三方模型资产。

## 6. 应用到实体与脚本

- [ ] 右侧绑定页选一个真实 UUID（不是 type），预设页选一个已保存预设。
- [ ] 点击“在选定实体上播放”；它只播放已保存预设，不替实体更换模型，需要 OP，拒绝使用未保存草稿。
- [ ] 关闭界面，用 `/yhysm inspect` 和 `/yhysm state <UUID>` 查看请求、服务端信号、实际 OYSM 选中项及跳过原因。
- [ ] “停止实体的手动动作和表情”只清显式请求，自动规则及旧符卡提示恢复，不删除绑定。
- [ ] 聊天框输入 `/yhysm anim play <UUID> ` 后按 Tab，应出现该实体模型的真实动画；`param set <UUID> ` 补全参数，参数后补全原生开关/数值选项，`param get/clear` 也补全参数。
- [ ] `preset list`/`preset apply` 补全模型及该模型已保存预设；确认完整命令仍由服务端执行，OP 与选择器规则不变。

命令（含 Unicode、空格或 `/` 的模型 ID 请加双引号）：

```text
/yhysm preset list "实际模型ID"
/yhysm preset apply <UUID或服务端选择器> "实际模型ID" happy [ticks]
/yhysm anim play <targets> extra5 100
/yhysm param set <targets> v.roaming.mouth 2 100
/yhysm clear <targets>
```

命令补全优先使用可见目标的有效模型；无法在客户端解析目标时回退到本地模型/共享预设合集，
这时可能包含其他模型的条目。补全只是建议，执行仍由服务端校验。Editor 内候选限定到选中模型。

服务端 KubeJS 已持有 YH 实体时：

```js
const model = '从 Editor 目录复制的模型 ID'
if (YHModel.supports(entity)) {
    const groups = YHModel.listPresets(entity, model)
    if (groups.contains('happy')) {
        YHModel.applyPreset(entity, model, 'happy', 100)
    }
}
```

脚本全契约、查询范围和错误处理见 `docs-dev/yhmodel-script-api.md`。
模型限定的预设不会错误套到另一个模型；底层 `play/setParameter` 则有意跟随实体当前模型。

## 7. 协作与恢复

- [ ] 保存时如提示版本冲突，当前草稿仍保留：先导出，再“重载草稿”取服务器新版本，合并后重试。
- [ ] 绑定冲突使用“重读目标绑定”获取新版本；绑定版本独立于模型预设版本。
- [ ] 超时表示结果未知，不能认为一定失败。检查连接，重读确认，避免反复覆盖。

保存位置：`<世界>/data/youkaishomecoming_model_profiles.dat`，已有绑定仍在
`<世界>/data/youkaishomecoming_ysm_overrides.dat`。预设不是只保存在客户端。
运行中的显式动作/参数和行为信号是瞬态同步字段，不写实体存档；实体卸载后重新加载会重新采样行为。

## 限制与排障

- 当前仅支持 LOOP + 有效期；不承诺 PLAY_ONCE、保持末帧或晚加入者逐帧相位一致。
- 模型延迟加载时不会重新获得完整持续时间；过期请求不会重新播放。
- 清除参数恢复当前有效基础值，不盲写 0。模型脚本自己覆盖输入时可能仍影响结果；这不是全变量沙盒。
- “模型目录未就绪”先等待实际模型加载；“缺片段”换真实目录里的 clip。缺资源不改动模型包白名单/骨骼。
- 无 OYSM 时仍能手填模型并编辑/导入共享配置，目录和模型专属预览会降级；普通 YH/TLM/原版回退不应被阻断。
- 没有批量修补所有模型资产，也没有实现通用骨骼重定向。

## 实机发布门槛（按实际覆盖范围登记）

本轮不追加自动 smoke 或大量代码测试。以下画面、交互和联机项必须在游戏内确认，不能用编译结果代勾。

- [ ] 装 OYSM：上述工作流程可操作，预览转动/缩放、表情恢复、同片段重播正常。
- [ ] 单人：保存不因暂停卡死；关闭/重新打开、重启世界保留预设和绑定。
- [ ] 两名客户端：保存传播、两人同时编辑同模型冲突、无 OP 修改被拒绝，且其他玩家绑定表未被清空。
- [ ] 两名观察者：持续表现一致；晚进入跟踪范围只剩余计时；切换模型、重载模型/资源、断线无残留覆盖。
- [ ] 本修订构建同时无 OYSM、无 TLM：专服与客户端启动、打开 Editor 和配置编辑降级正常。旧构建结果不能代替本次复查。
- [ ] 仅装 OYSM、仅装 TLM 的组合分别启动，确认目录/预览按实际能力工作，既有委托回退不受阻。
